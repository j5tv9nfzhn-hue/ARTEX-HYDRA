# 专家级证据复核、3-Strike 止损与漏洞真实性门禁 (expert-triage-pivot)

本技能包用于解决渗透测试与逆向工程中最致命的两大问题：**① 在当前未获有效证据的接口上盲目穷举数十轮导致超时 (`exhausted`)**；**② 把框架默认行为或信息级现象误判为高危漏洞**。

---

## When to Use

- 同一端点或同一参数连续 3 次收到同质化负面响应（如固定 `422 Unprocessable Entity`、固定字节数的 `500 Internal Server Error`、固定 `401/403` 或 WAF 拦截页）时。
- 工具返回结果中出现 **`[执行层止损 / 3-Strike]`** 或 **`loop_blocked`** 时。
- 准备调用 `report_finding` 上报漏洞前，进行最终真实性与危害度自检时。

---

## Procedure

### 1. 3-Strike 专家止损与转向铁律（3-Strike Circuit Breaker）

重复负反馈是止损依据，不是后端实现或无漏洞的证明。根据授权、预算与已得证据控制尝试次数，观察、假设和结论分开记录：

1. **Strike 1（基准与边界探针）**：发送正常基准包 + 1 个最小语法破坏探针（如单引号 `'` 或越界 ID），观察状态码、响应体字节数、错误类型与耗时。
2. **Strike 2（语义正交探针）**：若 Strike 1 被拦截或报错，换一个**完全不同机制**的探针（例如从语法破坏换为合法格式下的跨账号 ID / 布尔恒真对比）。
3. **Strike 3（通道/层级正交探针）**：若仍返回完全相同的静态错误（如 `422 string_type` 或固定长度 `500`），仅说明本轮输入与观察未验证该假设；不能排除其他路径、上下文或同类问题。
4. **立即裁决（Pivot or Conclude）**：
   - **严禁第 4 次发送同类变体（如换 URL 编码、换注释符 `--` / `#`、换 SQL 函数名）！**
   - 向 `record_fact` 附原始响应和请求条件，写明“本次未验证该假设”；仅在有独立证据时描述具体校验机制，不把推断写为已确认事实；
   - 若本意图还有其他攻击维度（如逻辑越权、并发竞争），立即切换维度；若本意图就是专门验证该猜想，**输出已观察结果、限制与未验证范围后结束该尝试**；只有充分证据支持时才使用“证伪”。

---

### 2. 上报漏洞前的“专家五问门禁”（5-Question Triage Gate）

在调用 `report_finding` 之前，必须逐条回答以下 5 个问题，**任一问题回答为“否”，一律降级为 `record_fact` 而禁止调用 `report_finding`**：

| 序号 | 专家自检问题 | 典型误报反例（禁止上报 `report_finding`） |
|---|---|---|
| **Q1** | **是否突破了安全边界？**（读取/修改了无权访问的数据，或绕过了强制认证步骤） | 拿着用户自己的合法 Token 查询自己的资料返回 200；或者未带 Token 访问公开配置接口。 |
| **Q2** | **响应体是否包含真实敏感数据或状态变更证明？** | 越权请求虽然返回 `200 OK`，但响应体是 `{"data":[],"total":0}` 或通用错误提示。 |
| **Q3** | **是否排除了框架默认行为与无害状态差分？** | 传入非法格式返回 `422`、传入不存在的 Token 返回 `500`、传入过期 Token 返回 `400`（无堆栈泄露且无法枚举有效凭据）。 |
| **Q4** | **证据链是否自包含且可一键复现？** | 只写了“存在越权风险”却没有贴出请求头/请求体、响应体关键字段以及对应的 `exchange_id`。 |
| **Q5** | **是否已检查本任务 `list_findings` 确认未重复上报？** | 同一个根因（如全局 CORS 配置或同一个未鉴权接口）在多个子路径被重复报成 5 个独立漏洞。 |

---

## Pitfalls

- **把“穷举完字典”误当成“尽职尽责”**：Worker 应减少没有新证据的重复请求，把预算留给真正有状态差分的高价值链路。
- **忽略 Planner / 用户的实时纠偏指令**：当对话中出现用户或 Planner 注入的转向指令时，必须第一时间响应，停止原有旧路径。

---

## Verification

- 每次成功止损结束任务时，输出结构应包含：**① 已测试的正交探针矩阵（≤3 组）**、**② 已观察响应、待验证的机制假设与未验证范围**、**③ 建议 Planner 后续优先探索的相邻高价值方向**。


## 执行层止损的真实范围

当前硬门禁仅对单次运行内的 `http_request` / `http_fuzz` 同键后续调用生效，不控制一次批量调用内的每个请求，不覆盖 Bash、MCP 或下一执行轮。它不是安全沙箱。不要为绕过止损更换无关参数；重新评估应基于新证据与明确授权。
