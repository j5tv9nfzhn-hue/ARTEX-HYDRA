> 本文档为技能包支撑文件（`references/pitfalls-and-bypasses.md`），汇总从实战报告中提炼的全部**易错陷阱、失败根因、底层绕过技术与 3-Strike 止损矩阵**。

## 1. 为什么在渗透与逆向中「过程与踩坑」比最终产物更重要

- **防死循环**：AI 在面对预签名校验、软链接防御、受限沙箱或无回显 SSRF 时，若只知道最终漏洞名称而不知道前置踩坑过程，极易在标准 HTTP 客户端路径归一化、静态软链接拦截或无效盲注上耗尽 Token。
- **因果可迁移**：目标域名、具体接口名会随项目改变，但「前端 WASM 签名逆向 → 原始未归一化路径直传」、「`renameat2` 原子交换绕过 `realpath` 检查」、「从沙箱进程环境提取内部密钥反打控制面」的推导链可跨目标直接复用。

### 2.14 陷阱 4：拿到沙箱 RCE 或任意文件读取后只停留在当前容器，忽略宿主机共享 UID 与环境变量密钥横向接管

- **常见踩坑现象与误区**：
  许多轻量级沙箱并非独立容器，而是直接以宿主机普通用户（如 `uid=1001`）跑在宿主机进程空间，或与主 API 进程共享环境变量与源码目录。如果只看当前工作目录，会漏掉整个控制面与计费系统的彻底沦陷。
- **底层根因与破局绕过方案**：
  立即读取 `/proc/self/environ`、父进程环境及宿主机源码配置（如 `config.py` / `.env`），提取内部共享密钥（如 `WEB_SERVER_SECRET`、`TRUSTED_SERVICE_SECRETS`）和第三方付费 Key（`OPENROUTER_API_KEY`、`FALAI_KEY`），再用提取到的内部 Header（`X-Internal-Secret`、`X-Trusted-Service`）直接调内部计费、配额免除与 GPU 控制面接口。
- **止损与切换信号（3-Strike Rule）**：
  读取环境变量与配置后优先做密钥可用性最小验证（如 `/api/internal/verify/`），禁止对第三方付费 API 发起高额消耗请求。
- **验证探针摘录**：

```text
Header: X-Internal-Secret / X-Trusted-Service 解锁 /api/internal/* 与 /v1/gpu/reset/*
```
