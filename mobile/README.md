# ARTEX 移动端接入（不做双端 App）

**结论先行**：不把 PC 端功能搬到手机上——那是冗余设计。
有服务器的人用公网面板，只在本机用的人用远程桌面或 IM Bot 指挥。
本目录记录这条策略、缺口清单与落地轮次。

| 通道 | 面向 | 本质 | 状态 |
| --- | --- | --- | --- |
| **A 公网面板** | 有服务器 / 会开反代的人 | 把已在的 Web 面板做成窄屏可用 + 可安装（PWA）+ 安全加固 | 缺 PWA 与窄屏收尾 |
| **B 远程桌面** | 只在本机用的人 | 零开发，要一份手册（Sunshine/Parsec/Todesk 选型与配置） | 未写手册 |
| **C IM Bot 指挥** | 两类都适用 | 在聊天软件里发一句话指挥 PC；App 由 Bot 平台自带 | 出站已有，入站缺失 |

## 现状实测（关键缺口）

- `notify/` 有 telegram / feishu / dingtalk / wecom / email / webhook / http 七种**出站**通知；
  全仓没有 `getUpdates` / `setWebhook` / inbound handler → **入站命令要新增**。
- `mcpserver/` 有 Bearer 鉴权与 `tools/list` / `tools/call`，但暴露的是扫描工具，
  **没有会话控制面**（列会话 / 拉对话 / 停任务 / 审批）→ 需 MCP 化，Bot 才能指挥。
- `web/` 无 `manifest.json`、无 `apple-mobile-web-app` 声明 → 面板现在只能当网页用，不能"装"。
- 面板构建产物由 Go 内嵌提供（`server/assets.go`），远程访问 = 反代/Tunnel + TLS，无需另起服务。

## 铁律（沿用仓库约定）

- 本目录是**文档为主**，移动端同样不做本地构建（不跑 `npm` / `go build` / `gomobile`）。
- 手机端不跑 agent、不跑 Bash、不跑代理；不复制数据模型；不追求功能对齐 PC。
- 手机只保留三类动作：**看进度 / 说一句话 / 停或批**。
