# ARTEX 手机端 = 总控台（独立设计，不是网页缩小版）

**定位**：手机端不是 PC 工作台的搬运，也不是公网 web 面板的缩小版，而是**驾驶舱**——控制管理、信息与流量消耗、完整通知（含系统提示）、进度展示、模型消耗。

**两条硬边界**

1. **功能不搬运**：手机看全局与结论，PC 看细节与编辑（编辑器 / diff / 长文 / 终端一律回 PC）。
2. **界面不复用**：独立设计一套原生 UI，不 import `web/` 的任何组件与样式；只共享 API 契约与数据类型。
   否则用户一眼看出是网页套壳，会直接问：**为什么不打开公网面板？**

## 手机端必须给出的 7 件网页给不了的东西

| # | 能力 | 公网 web 面板 | 原生 App |
|---|---|---|---|
| 1 | **锁屏推送** | iOS Safari 的 Web Push 需 16.4+ 且必须"添加到主屏"，后台策略随时变 | APNs/FCM，进程不在也能到 |
| 2 | **通知中心直达** | 只能靠页面内轮询 | 点通知直接进对应任务/漏洞/审批卡片 |
| 3 | **离线可读** | 断网即白屏（除非另做 SW 缓存） | 本地缓存最后状态，电梯里也能看 |
| 4 | **手势快操作** | 无（只有点击） | 左滑停止任务、右滑已读、长按静音 |
| 5 | **主屏角标** | 无 | 未读数常驻图标，不打开也知道有事 |
| 6 | **首屏即结论** | 打开→登录→找菜单→进页面 | 一屏四卡：在线/运行/待审/消耗 |
| 7 | **生物识别解锁** | 每次输密码或长期保持登录 | Face ID / 指纹解锁，安全与省事兼得 |

这 7 条里有 4 条以上做不到，就不该发 App；做到了，"为什么不直接用网页"这个问题就自动消失。

## 五块功能（范围）

| # | 功能 | 手机上要看到什么 | 手机上能做什么 |
|---|---|---|---|
| 1 | **总控控制管理** | 服务是否在线、当前任务数/运行中/排队、拦截与审批待办数、资产数与流量数、引擎模式 | 启停/暂停任务、切换活跃任务、批准或拒绝审批、重试失败任务、切模型档位 |
| 2 | **信息消耗面板** | 今日/本周资产增量、流量条数、抓到的请求数、拦截命中、缓存命中率 | 按任务/按类型钻取；导出或复制摘要 |
| 3 | **完整通知（含系统提示）** | 漏洞（分级）、审批请求、任务失败、阶段完成、系统提示/告警（磁盘、限流、自更新、token 失效） | 已读/忽略/静默、按级别过滤、点通知直达对象、二次确认后一键处理 |
| 4 | **进度展示** | 阶段 → 步骤 → 当前工具与耗时；已完成/剩余；实时增量（工具行在跑的时候会长） | 暂停/停止、看当前输出尾部、失败步骤重试 |
| 5 | **模型消耗** | 输入/缓存/输出 token、按模型与按任务、当日累计、预算使用率、异常放大提醒 | 切模型档位、设预算阈值、查看 LLM 记录明细（只读） |

一句话边界：**手机看"全局与结论"，PC 看"细节与编辑"。**

**明确不做（防止范围回弹）**

- 不做代码编辑器 / diff 审阅 / 长文写作 / 终端交互。
- 不做"功能对齐 PC"的移植清单——只做上面五块。
- 不在手机端跑 agent、代理、扫描、Bash；不复制数据模型，只做"视图 + 控制面"。
- 不做自研推送体系之外的第三方分析 SDK。
- 任何"顺手把 PC 功能搬上手机"的需求，先问"远程桌面能不能代替"。

结论：**手机端 = 这些接口的独立原生 UI + 推送 + 常驻入口**。接口与字段口径复用，**界面不复用**。

## 通知分级（成败关键）

| 级别 | 事件 | 是否推送 | 聚合 |
|---|---|---|---|
| **P0** | 高危/严重漏洞、待审批（会阻塞 PC 进度）、任务失败、服务掉线 | 立即推 | 不聚合 |
| **P1** | 任务阶段完成、总进度跨过 50%/100%、预算跨过 80% | 推 | 5 分钟内合并为一条 |
| **P2** | 系统提示（磁盘、限流、自更新完成、token 即将过期）、低危漏洞 | 只进收件箱 | 每小时摘要 |

- 静默时段可配；静默期间 P0 仍然推（否则等于没有通知）。
- 全量入库，推送只是"提醒"；**收件箱永远可回溯**——这是"完整通知"的落点。

## 四屏信息架构

```
[总览]  大数字卡：在线/运行中/待审批/高危漏洞 + 今日 token 与成本 + 最近 5 条通知
[任务]  列表(运行中/排队/已完成) → 详情：阶段进度条 + 当前工具流尾部 + 停止/重试
[通知]  分级收件箱：P0 高危&审批&失败 / P1 阶段完成 / P2 系统提示；未读角标
[消耗]  输入·缓存·输出三色条 + 按模型/按任务切换 + 预算使用率 + 7 日柱状
```

每屏只回答一个问题：

- **总览 ——"现在有事吗？"** 一个大 KPI（如"待处理 3"）+ 2×2 次级卡（运行中任务 / 高危漏洞 / 待审批 / 今日花费）；一条横向状态带（服务在线、引擎模式、最后活动时间）；最近 3 条通知内联预览。空态给绿色"一切正常"+ 最后活动时间；错态给断开原因 + 重试按钮（不是转圈）。
- **任务 ——"跑到哪了？"** 列表置顶运行中（进度环 + 当前工具名），左滑停止/暂停，长按复制任务 ID；详情含阶段进度条、当前工具与已耗时、最近 5 行输出（可展开）、底部悬浮"停止"；失败态给红色步骤 +"重试此步"，不整页重跑。
- **通知 ——"发生了什么？"** P0（红点）→ P1 → P2（折叠）；卡片含级别色条、图标、标题、一行摘要、相对时间与右侧动作；右滑已读、左滑静音同类；顶部 chip 过滤（全部/未读/仅高危）；审批卡片必须写清"将执行什么"，按下前二次确认。
- **消耗 ——"花了多少？"** 顶部输入/缓存/输出三色比例条（不是饼图）；按模型/按任务切换 + 7 日柱状；预算环形进度 + 剩余额度 +"80% 提醒"开关；某任务 token 突增时红色三角标记并可钻取。

交互约定（手机优先）：

- **一屏一结论**：首屏不做滚动长列表，四张卡就能判断"要不要管"。
- **推送直达**：每条推送带深链，点开即到对象（任务/漏洞/审批），不是到首页。
- **危险动作二次确认**：停止任务、批量审批、改预算，都要一次确认；审批卡片显示"将执行什么"。
- **轮询优于长连接**：前台 5–10s 轮询 `/api/stats`，后台不发请求；实时流只在任务详情页开。
- **触达**：主要动作在屏幕下 2/3，触控 ≥ 48dp / 44pt，单手可用。

## 设计语言：深色驾驶舱

不做"明亮后台风"，做**值班室里的仪表**：暗底、少色、数字大、状态色只用来报警。

| Token | 取值 | 说明 |
|---|---|---|
| 底色 | `#0B0E14` / 卡片 `#141924` | 深色为默认（实现提供明暗双套，见「已落地」） |
| 状态色 | 正常 `#22C55E` · 注意 `#F59E0B` · 危急 `#EF4444` · 静止 `#64748B` | **只用于状态**，绝不装饰 |
| 主色 | `#38BDF8` | 仅用于可点元素与选中态 |
| 数字 | 等宽 tabular-nums，主 KPI 44–56pt | 防跳动；一屏只有一个"最大数字" |
| 触达 | ≥ 48dp / 44pt；主要动作在屏幕下 2/3 | 单手可用 |
| 圆角 / 间距 | 卡片 16 / 内 16 / 组间 24 | 统一节奏 |
| 动效 | 数值变化 200–400ms，进度条平滑推进 | 超 400ms 会显得卡 |
| 导航 | 底部 4 tab：总览 / 任务 / 通知 / 消耗 | 设置放总览右上，不进 tab |

## 技术选型：React Native + Expo

| 维度 | **RN + Expo（选用）** | Capacitor（web 复用） | Flutter | 纯原生 |
|---|---|---|---|---|
| 渲染 | 原生组件（Fabric） | WebView | 自绘（Impeller） | 原生 |
| 被当成"网页壳"的风险 | 低 | **高**（WebView 同源，商店对薄壳敏感） | 低 | 低 |
| 语言 | TypeScript（团队已有 React/TS） | TS | Dart（新语言） | Swift + Kotlin 两套 |
| 推送 | `expo-notifications` 内置，证书由 EAS 托管 | 需插件绕 | 需插件 | 各自实现 |
| 免商店热更 | EAS Update | Appflow | Shorebird（第三方） | 无 |
| 双端成本 | 一套代码 | 一套代码 | 一套代码 | 两套 |

选它的**唯一决定性理由**：与"把 web 缩小"划清界限的同时，不引入新语言——团队写 TS/React，直接产出原生组件。**Capacitor 主动排除**（就是"网页装壳"），Flutter 也排除（界面是卡片 + 数字 + 少量图表，原生组件够用，不值得多学一门语言）。

**发布与推送**：EAS Build 云构建（iOS 无需本地 macOS，证书与描述文件由 Expo 托管）、EAS Update 做 JS 层热更；推送走 APNs + FCM，由 `expo-notifications` 统一，token 上报 `/api/mobile/push/register`；节奏 TestFlight 内部 → 小范围 → 商店。

## 三条通道（怎么连上，与「做什么」分开）

| 通道 | 角色 | 说明 |
|---|---|---|
| **A 原生 App（RN + Expo）** | **主容器** | 四屏界面独立设计，不复用 web 组件 |
| **B 公网面板（浏览器）** | 兜底与桌面场景 | 不在手机主屏装 App 时临时用；缺口是窄屏可用性、可安装（PWA）、公网暴露加固 |
| **C IM Bot 指挥** | 推送与一句话指令 | P0/P1 通知落到聊天软件；`/list`、`/stop`、`/approve`、`/status` 短命令 |
| **D 远程桌面** | 兜底 | 需要看 diff、改长文、调复杂配置时才用，不替代总控台 |

即：**面板管"看与管"，Bot 管"提醒与快令"，远程桌面管"重活"**。状态只存在服务端一份，手机看到的是同一份，不需要同步协议。

IM Bot 现状与缺口（实测）：

| 能力 | 现状 | 缺口 |
|---|---|---|
| 出站通知 | ✅ `notify/` 七通道齐全，事件驱动 | — |
| 入站命令 | ❌ 全仓没有 `getUpdates` / `setWebhook` / inbound handler | 需新增入站适配器（优先级：Telegram long-poll > 飞书事件订阅），命令白名单 + 高危二次确认 + 全量审计 |
| 会话控制面 | ⚠️ `mcpserver/` 有 Bearer 鉴权与 `tools/list` / `tools/call`，但暴露的是扫描工具 | 需把 `conversation.list/tail/send`、`task.stop`、`approval.decide` 等控制面 MCP 化 |
| 现成机器人 | ✅ 可用 OpenClaw 一类自托管 Gateway 接 20+ 渠道 | 只需让 Gateway 能调到 ARTEX |

**不做双端 App 的理由**（历史决策，保留依据）：有服务器的人直接开公网面板就够；只在本机用的人用远程桌面 + IM Bot 更短。省掉的成本是双端两套签名与商店审核、iOS 开发者账号、APNs/FCM 证书维护、每次 PC 侧改 UI 都要重新发版。`mobile` 目录的意义不是"造 App"，而是**把已存在的能力接到手机上**；而正式手机体验仍由独立设计的原生 App 承担。

## Go 与移动端适配度（否决证据）

若要给"为什么不在手机端跑 Go 内核"一个可复核的依据：

- **Go 能上手机，但只能当被调用的库**：`gomobile bind` 产 `.aar` / `.xcframework`，UI 仍是 Kotlin/Swift。
- **跨语言边界能力被裁剪**：只支持有符号整数、浮点、`string`、`bool`、`[]byte` 及由这些组成的结构体/接口；**泛型让 bind 直接失败**，`any` / `map` / `chan` / `func` 参数被**静默跳过**，panic 跨边界直接杀进程。ARTEX 现有代码大量 `map[string]any` 与回调，要复用就得再写一层 bind 安全门面——用 HTTP + JSON 做同样的事成本更低。
- **体积**：空库 Android 四架构 AAR ≈ 8.4 MB；真实同步/网络库 arm64 `.so` 27.4 MB、iOS 静态 framework 35 MB。
- **构建约束**：iOS 必须 macOS + Xcode；Android NDK 27 起必须 `-androidapi 21`。
- **iOS 后台限制**：进后台 socket 被挂起，"手机端常驻长连接做实时同步"不成立，必须改成"前台实时 + 推送唤醒 + 打开时拉增量"。
- **匹配度**：执行 Bash/工具 ❌、本地 CA/mitmproxy ❌、本地 SQLite ⚠️（一致性变成新问题）；看会话/下指令 ✅ 但用 WSS/REST 更简单。

`gomobile` 只在"手机端真的要跑离线引擎"时才局部引入；ARTEX 不需要。

## 现状实测（关键缺口）

- **数据基本齐了**：`/api/stats` 与 dashboard 的聚合口径可直接对齐，不新造业务（但界面另写）。
- `notify/` 七路**出站**齐全，但全仓无入站 handler → 入站命令要新增。

## 已落地（2026-10-22 · 提交 `8ea4432`）

**后端（Go）**

| 接口 | 说明 |
|---|---|
| `GET /api/mobile/overview` | 总览一次拉全：引擎状态、运行/排队/暂停、未读告警（含按级别）、今日 token、资产与流量 |
| `GET /api/mobile/alerts?limit&since_id&level&unread` | 分级收件箱，附未读总数与按级别分布 |
| `POST /api/mobile/alerts/read` `{ids}` | 标记已读 |
| `POST /api/mobile/alerts/read-all` | 清空未读 |
| `GET /api/mobile/usage?days=7` | 近 N 天 token 曲线 + 按配置档分布（金额口径仍在 web） |
| `GET /api/mobile/tasks` | 任务完成度：按目标达成率给出 0..1，无目标返回 `-1`（界面画灰环，不假装 0%） |
| `POST /api/mobile/push/register` `{platform,token,device}` | 设备推送凭据注册 |
| `DELETE /api/mobile/push/register?token=` | 注销设备 |

- 新增表：`mobile_alerts`（收件箱，含 `read_at`）、`mobile_push_tokens`（设备凭据）。
- `server/ui_notify.go` 的 UI 事件**异步落库**，手机收件箱因此可回溯、可统计未读；落库失败不影响原内存通知。
- 任务控制复用 `POST /api/tasks/control/batch`（只支持 `pause` / `resume`；ARTEX 的「停止」即暂停）。
- 审批复用 `GET /api/intercept/pending` 与 `POST /api/intercept/pending/{id}/decide`。

**前端（Expo + React Native + TypeScript）**

- 明暗**双色系统**：`src/theme/tokens.ts` 两套完整 token，`ThemeProvider` 支持「跟随系统 / 浅色 / 深色」并持久化。
- 四屏：总览 / 任务 / 通知 / 消耗；另有登录（服务器地址 + 密码）、设置、任务详情。
- 数据层：`usePoll` 轮询（前台 8–10s，后台不请求），Bearer 鉴权，令牌存 `expo-secure-store`；缓存键支持请求失败时回落到上次成功载荷，页脚标注「缓存数据 · 更新时间」。
- 组件全部自写（Card / StatNumber / StatusDot / ProgressRing / Bars / Chip / Empty / Screen），**与 `web/` 零复用**。

**CI**：`.github/workflows/mobile.yml`（`npm install` + `tsc --noEmit`）自 v1.0.0 起为**硬门禁**；`.github/workflows/mobile-build.yml` 出 Android APK 与 iOS 模拟器 `.app`（artifact 保留 14 天）。

## 铁律

- 移动端同样不做本地构建（不跑 `npm` / `npx expo` / `go build`）。
- 手机端不跑 agent、不跑 Bash、不跑代理；不复制数据模型。
- 危险动作（停止、批量审批、改预算）一律二次确认。
