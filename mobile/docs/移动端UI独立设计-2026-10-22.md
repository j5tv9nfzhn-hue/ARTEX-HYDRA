# 手机端 UI：独立设计，不复用 web 前端

> **本轮决定**：手机端界面**从零设计**，不导入 `web/` 的任何组件、样式与页面结构。
> 复用的只有**接口契约与数据类型**（`/api/*` 的字段口径）——因为那是数据，不是界面。
> 复用界面的后果很具体：用户一眼认出"这就是把网页缩小了"，然后合理地反问：**为什么不直接开公网 web 面板？**
> 我们必须在**每一屏**都给出网页给不了的东西，否则这个 App 就没有存在理由。

## 1. 网页给不了的 7 件事（App 的存在理由）

| # | 能力 | 公网 web 面板 | 原生 App |
| --- | --- | --- | --- |
| 1 | **锁屏推送** | iOS Safari 的 Web Push 需 16.4+ 且必须"添加到主屏"，后台策略随时变 | APNs/FCM，进程不在也能到 |
| 2 | **通知中心直达** | 只能靠页面内轮询 | 点通知直接进对应任务/漏洞/审批卡片 |
| 3 | **离线可读** | 断网即白屏（除非另做 SW 缓存） | 本地缓存最后状态，电梯里也能看 |
| 4 | **手势快操作** | 无（只有点击） | 左滑停止任务、右滑已读、长按静音 |
| 5 | **主屏角标** | 无 | 未读数常驻图标，不打开也知道有事 |
| 6 | **首屏即结论** | 打开→登录→找菜单→进页面 | 一屏四卡：在线/运行/待审/消耗 |
| 7 | **生物识别解锁** | 每次输密码或长期保持登录 | Face ID / 指纹解锁，安全与省事兼得 |

只要这 7 条里有 4 条以上做不到，就不该发 App；做到了，"为什么不直接用网页"这个问题就自动消失。

## 2. 技术选型：React Native + Expo

| 维度 | **RN + Expo（推荐）** | Capacitor（web 复用） | Flutter | 纯原生 |
| --- | --- | --- | --- | --- |
| 渲染 | 原生组件（Fabric） | WebView | 自绘（Impeller） | 原生 |
| 被当成"网页壳"的风险 | 低 | **高**（WebView + 与网页同源，商店对薄壳也敏感） | 低 | 低 |
| 语言 | TypeScript（团队已有 React/TS） | TS | Dart（新语言） | Swift + Kotlin 两套 |
| 推送 | `expo-notifications` 内置，证书由 EAS 托管 | 需插件绕 | 需插件 | 各自实现 |
| 免商店热更 | EAS Update | Appflow | Shorebird（第三方） | 无 |
| 双端成本 | 一套代码 | 一套代码 | 一套代码 | 两套 |

选它的**唯一决定性理由**：与"把 web 缩小"划清界限的同时，不引入新语言。团队写的是 TS/React，直接产出原生组件，不用 WebView。

Flutter 的强项是自绘一致性与图表性能（桌面级像素控制），但我们这套界面是**卡片 + 数字 + 少量图表**，原生组件够用，不值得为它多学一门 Dart。
Capacitor 在这里**主动排除**：它就是"网页装壳"，正好是我们这次要避免的形态。

## 3. 设计语言：深色驾驶舱

不做"明亮后台风"，做**值班室里的仪表**：暗底、少色、数字大、状态色只用来报警。

| Token | 取值 | 说明 |
| --- | --- | --- |
| 底色 | `#0B0E14` / 卡片 `#141924` | 深色为默认（无浅色主题 v1） |
| 状态色 | 正常 `#22C55E` · 注意 `#F59E0B` · 危急 `#EF4444` · 静止 `#64748B` | **只用于状态**，绝不装饰 |
| 主色 | `#38BDF8` | 仅用于可点元素与选中态 |
| 数字 | 等宽 tabular-nums，主 KPI 44–56pt | 防跳动；一屏只有一个"最大数字" |
| 触达 | ≥ 48dp / 44pt；主要动作在屏幕下 2/3 | 单手可用 |
| 圆角 / 间距 | 卡片 16 / 内 16 / 组间 24 | 统一节奏 |
| 动效 | 数值变化 200–400ms，进度条平滑推进 | 超 400ms 会显得卡 |
| 导航 | 底部 4 tab：总览 / 任务 / 通知 / 消耗 | 设置放总览右上，不进 tab |

## 4. 四屏 IA（每屏只回答一个问题）

### 4.1 总览 —— "现在有事吗？"
- **头字号**：一个大 KPI（如"待处理 3"），下面 2×2 次级卡：运行中任务 / 高危漏洞 / 待审批 / 今日花费。
- 一条横向状态带：服务在线、引擎模式、最后活动时间（相对时间）。
- 最近 3 条通知的内联预览，右侧"全部"。
- 空态：绿色"一切正常" + 最后一次活动时间；错态：断开原因 + 重试按钮（不是转圈）。

### 4.2 任务 —— "跑到哪了？"
- 列表：运行中（置顶，带进度环与当前工具名），排队，最近完成。
- 左滑 → 停止 / 暂停；长按 → 复制任务 ID。
- 详情：阶段进度条（阶段名 + 第几步/共几步）、当前工具与已耗时、最近 5 行输出（可展开）、底部悬浮"停止"。
- 失败态：红色步骤 + "重试此步"，不整页重跑。

### 4.3 通知 —— "发生了什么？"
- 分级收件箱：P0 段（红点）→ P1 → P2（折叠）。
- 卡片：级别色条 + 图标 + 标题 + 一行摘要 + 相对时间 + 右侧动作（批准/拒绝/查看）。
- 右滑已读，左滑静音同类；顶部 chip 过滤（全部/未读/仅高危）。
- 审批卡片必须写清"将执行什么"，按下前二次确认。

### 4.4 消耗 —— "花了多少？"
- 顶部三色条：输入 / 缓存 / 输出（比例条，不是饼图）。
- 切换维度：按模型 / 按任务；下方 7 日柱状（sparkline 亦可）。
- 预算：环形进度 + 剩余额度 + "80% 时提醒"开关。
- 异常态：某任务 token 突增 → 红色三角标记，点进去看该任务分项。

## 5. 组件与代码组织（自有，不 import web）

```
mobile/            （未来实际工程，RN + Expo Router）
├── app/           (tabs)/overview · tasks · alerts · usage
├── src/ui/        自有基础组件：Card / StatNumber / StatusDot / ProgressRing / Sheet / SwipeRow
├── src/features/  overview / tasks / alerts / usage（每个含 api + hooks + screens）
└── src/api/       仅类型与请求函数，字段来自 openapi/types 生成，不 import web 组件
```

- **共享边界**：允许共享 TS 类型定义与接口契约；**禁止**共享 `.tsx` 组件、样式、i18n 词条文件。
- 图标、日期、数字格式各自实现（移动端 44pt 触达与 tabular 数字要求与 web 不同）。

## 6. 发布与推送

- **EAS Build** 云构建（iOS 无需本地 macOS，证书与描述文件由 Expo 托管）；**EAS Update** 做 JS 层热更（商店外修复小问题）。
- 推送：APNs（iOS）+ FCM（Android），由 `expo-notifications` 统一；token 上报到 ARTEX 的 `/api/push/register`。
- 版本节奏：TestFlight 内部 → 小范围 → 商店；后端字段不改则无需重新审核。

## 7. 轮次 U1–U6

| 轮次 | 范围 | 验收 |
| --- | --- | --- |
| **U1 工程与骨架** | Expo 工程、4 tab 导航、深色 token、假数据 | 双端真机跑通，切换 tab 流畅，深色无闪白 |
| **U2 总览 + 消耗（只读）** | 接 `/api/stats` 与用量接口；下拉刷新 | 手机上的数字与 PC 面板逐项一致；断网显示缓存与时间戳 |
| **U3 通知收件箱** | 分级、已读、静音、深链 | 制造高危漏洞与失败任务，各出现一条并可点进对象 |
| **U4 任务进度与控制** | 列表→详情、进度环、输出尾部、左滑停止 | 手机上停止任务，PC 真的停；重连后进度不丢 |
| **U5 推送与审批** | APNs/FCM 接入、角标、审批卡片二次确认 | 锁屏 30s 内收到审批，点开批准后 PC 继续 |
| **U6 打磨与上架** | 空/错/离线态、Face ID、图标与启动图、TestFlight/内测 | 无网络、无数据、被吊销令牌三种情况都有明确文案与出口 |
