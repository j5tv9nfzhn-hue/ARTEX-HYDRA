# 手机端 = 总控台（范围、数据来源、轮次）

> 手机端**不做** PC 工作台的搬运，也**不是**只能"看一眼、点一下"的遥控器。
> 它是一个**驾驶舱**：控制管理 + 消耗面板 + 完整通知 + 进度展示 + 模型消耗。
> 传输方式（公网面板 / 远程桌面 / IM Bot）见 `移动端策略-三通道-2026-10-22.md`，本文只定**范围**。

## 1. 五块功能（这就是手机端的全部）

| # | 功能 | 手机上要看到什么 | 手机上能做什么 |
| --- | --- | --- | --- |
| **1 总控控制管理** | 全局驾驶舱 | 服务是否在线、当前任务数/运行中/排队、拦截与审批待办数、资产数与流量数、引擎模式 | 启停/暂停任务、切换活跃任务、批准或拒绝审批、重试失败任务、切模型档位 |
| **2 信息消耗面板** | 情报与流量消耗 | 今日/本周资产增量、流量条数、抓到的请求数、拦截命中、缓存命中率 | 按任务/按类型钻取；导出或复制摘要 |
| **3 完整通知（含系统提示）** | 通知中心 | 漏洞（分级）、审批请求、任务失败、阶段完成、系统提示/告警（磁盘、限流、自更新、token 失效） | 已读/忽略/静默、按级别过滤、点通知直达对象、二次确认后一键处理 |
| **4 进度展示** | 任务进度 | 阶段 → 步骤 → 当前工具与耗时；已完成/剩余；实时增量（工具行在跑的时候会长） | 暂停/停止、看当前输出尾部、失败步骤重试 |
| **5 模型消耗** | Token 与成本 | 输入/缓存/输出 token、按模型与按任务、当日累计、预算使用率、异常放大提醒 | 切模型档位、设预算阈值、查看 LLM 记录明细（只读） |

一句话边界：**手机看"全局与结论"，PC 看"细节与编辑"。** 手机上写代码、看 diff、改长文，一律回 PC。

## 2. 数据来源（已在仓库里，实测有）

手机端不新造业务口径，全部复用现有页面已经用的接口：

| 面板 | 现有来源（实测） | 备注 |
| --- | --- | --- |
| 总控 | `GET /api/stats`（`server/server.go:1215`）：`engine_mode`、`llm_configured`、`traffic`、`assets`/`asset_counts`、`exploration`、goals/intents、`last_activity` | 已含 `?task=<id>` 绑定某个任务 |
| 总览聚合 | `web/src/app/(main)/dashboard/page.tsx`（1386 行）已经在聚合 `Stats / UsageStats / ConvTokenSummary / ReliabilityMetrics / Finding / InterceptPending / TrafficExchange / LLMProfile / Task` | **手机端直接对齐这套口径**，不另起一套 |
| 通知 | `notify/`（telegram/feishu/dingtalk/wecom/email/webhook/http 七路出站）+ `server/notify_api.go`、`server/ui_notify.go`、`server/task_notify.go` | 出站已有；缺"手机侧统一收件箱"与已读状态 |
| 审批 | `/system/intercept/approvals` 页 + `InterceptPending` 类型 | 手机要能批，且必须二次确认 |
| 漏洞 | `/function/findings`、`/function/findings/detail`、`Finding`、`severityTextClass` | 按高危优先排列 |
| 进度 | 任务详情 + 会话流（WSS/SSE 增量） | 手机只取"阶段+当前工具+最近 N 行" |
| 模型消耗 | `UsageStats`、`ConvTokenSummary`、`/function/llm-records`、`server/tool_usage.go`（`meterTool` 已按工具/agent 计量） | 已有分项计量，不需要新埋点 |

结论：**手机端 = 这些接口的窄屏视图 + 推送 + 常驻入口**，几乎没有新业务逻辑。这也是它便宜的原因。

## 3. 信息架构（4 屏，够用就好）

```
[总览]  大数字卡：在线/运行中/待审批/高危漏洞 + 今日 token 与成本 + 最近 5 条通知
[任务]  列表(运行中/排队/已完成) → 详情：阶段进度条 + 当前工具流尾部 + 停止/重试
[通知]  分级收件箱：P0 高危&审批&失败 / P1 阶段完成 / P2 系统提示；未读角标
[消耗]  输入·缓存·输出三色条 + 按模型/按任务切换 + 预算使用率 + 7 日柱状
```

交互约定（手机优先）：
- **一屏一结论**：首屏不做滚动长列表，四张卡就能判断"要不要管"。
- **推送直达**：每条推送带深链，点开即到对象（任务/漏洞/审批），不是到首页。
- **危险动作二次确认**：停止任务、批量审批、改预算，都要一次确认；审批卡片显示"将执行什么"。
- **轮询优于长连接**：前台 5–10s 轮询 `/api/stats`，后台不发请求；实时流只在任务详情页开。

## 4. 通知分级（成败关键）

| 级别 | 事件 | 是否推送 | 聚合 |
| --- | --- | --- | --- |
| **P0** | 高危/严重漏洞、待审批（会阻塞 PC 进度）、任务失败、服务掉线 | 立即推 | 不聚合 |
| **P1** | 任务阶段完成、总进度跨过 50%/100%、预算跨过 80% | 推 | 5 分钟内合并为一条 |
| **P2** | 系统提示（磁盘、限流、自更新完成、token 即将过期）、低危漏洞 | 只进收件箱 | 每小时摘要 |

- 静默时段可配；静默期间 P0 仍然推（否则等于没有通知）。
- 全量入库，推送只是"提醒"；**收件箱永远可回溯**——这是"完整通知"的落点。

## 5. 轮次 T1–T6

| 轮次 | 范围 | 交付物 | 验收（可观测） |
| --- | --- | --- | --- |
| **T1 只读总览** | 总览屏四卡 + `/api/stats` 轮询 + 窄屏适配 | 前端页面（复用 dashboard 口径） | 手机打开公网面板：不缩放即可读；任务变化 10s 内反映 |
| **T2 通知收件箱** | 统一收件箱、分级、已读、深链、聚合 | 新接口（列表/已读/静默）+ 页面 | 制造一次失败任务与一条高危漏洞：收件箱各出现一条，点开直达对象 |
| **T3 进度与任务控制** | 任务列表→详情、进度条、工具流尾部、停止/重试 | 前端 + 复用现有控制接口 | 手机上停止一个正在跑的任务，PC 端确实停下；进度条随阶段推进 |
| **T4 审批与推送** | 审批卡片（二次确认）、P0/P1 推送落地（IM 卡片或 PWA 推送） | 推送适配器 + 审批卡片 | 锁屏状态下 30s 内收到审批提醒，点开→批准→PC 继续跑 |
| **T5 消耗与预算** | 三色 token 条、按模型/任务、预算阈值与告警 | 复用 UsageStats/ConvTokenSummary | 消耗跨过 80% 时收到 P1 提醒；数据与 PC 面板同口径一致 |
| **T6 交付形态** | PWA 安装（默认） | manifest + 图标 + 全屏 | iOS 添加到主屏后独立图标、无地址栏；Android 有安装横幅 |

T6 若遇 iOS 推送不支持：**只**加一层薄壳（Capacitor）做推送与深链，不复制任何界面逻辑。

## 6. 与「三通道」的关系

| 通道 | 在手机端总控台里的角色 |
| --- | --- |
| 公网面板（PWA） | **主容器**：T1–T3、T5 的界面都在这里 |
| IM Bot 指挥 | **推送与一句话指令**：P0/P1 通知落到聊天软件；`/stop`、`/approve`、`/status` 短命令 |
| 远程桌面 | **兜底**：需要看 diff、改长文、调复杂配置时才用，不替代总控台 |

即：**面板管"看与管"，Bot 管"提醒与快令"，远程桌面管"重活"。**

## 7. 明确不做（防止范围回弹）

- 不做代码编辑器 / diff 审阅 / 长文写作 / 终端交互。
- 不做"功能对齐 PC"的移植清单——只做上面五块。
- 不在手机端跑 agent、代理、扫描。
- 不做自研推送体系之外的第三方分析 SDK。
