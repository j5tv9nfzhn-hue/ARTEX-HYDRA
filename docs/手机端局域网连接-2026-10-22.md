# 手机端（App）局域网连接

适用于手机 App 连接本机 ARTEX 服务。本次改动**只动服务端**，App 一行没改。

## 1. 为什么之前连不上

App 是一个胖 HTTP 客户端：登录页填「服务器地址 + 密码」→ 拿 Bearer token → 轮询 `/api/mobile/*`。
问题在于服务默认只监听 `127.0.0.1:8787`，`http://192.168.1.x:8787` 从手机上根本没有入口。

## 2. 开放局域网（三选一，都需重启服务）

| 方式 | 写法 | 适合 |
| --- | --- | --- |
| 命令行开关 | `artex-rea.exe -lan` | 临时开一次 |
| 命令行地址 | `artex-rea.exe -addr :8787` | 想指定端口 |
| 配置文件 | `config.json` 加 `"listen": ":8787"` | 一直开着 |
| 环境变量 | `ARTEX_LISTEN=:8787` | 脚本/容器 |

优先级：`-addr` > `-lan` > `ARTEX_LISTEN` > `config.json` 的 `listen` > 默认 `127.0.0.1:8787`。
`":8787"` 表示监听全部网卡；也可以写死某个内网地址，如 `"192.168.1.61:8787"`。

启动横幅下会直接列出手机该填的地址：

```
  手机端连接（把地址填进 App 的「服务器地址」，密码用 PC 端登录密码）
    http://192.168.1.61:8787
```

仍在回环上时会明确提示“App 连不上”并给出加 `-lan` 的做法，不会让人瞎试。

## 3. 防火墙

Windows 默认拦未放行的入站连接（管理员）：

```
netsh advfirewall firewall add rule name="ARTEX-REA" dir=in action=allow protocol=TCP localport=8787
```

Linux：`sudo ufw allow 8787/tcp`。macOS 第一次运行会弹系统提示，点允许即可。

## 4. App 一侧怎么填

登录页「服务器地址」填横幅里那个 URL（`http` 也行，代码会自动补协议），
密码用 PC 端登录密码。登录成功后 token 存在系统钥匙串（expo-secure-store），之后自动带上。
要求：手机与电脑在**同一局域网**（同一 Wi-Fi），且电脑防火墙已放行。

## 5. 安全

- 只在可信局域网开放；公寓/咖啡厅/公共 Wi-Fi 不要开。
- 要从外网访问，用 TLS 反向代理（Nginx/Caddy）对外，不要把 8787 直接映射到公网。
- 管理员密码未设置时，监听非回环地址会打开放警告（既有 `WarnIfExposed`）。
- 登录接口按源 IP 限流（既有 `authLimiter`），局域网建议输对一次就别重试太快。

## 6. 已知限制（本次按约定未改 App）

若手机在「已连同一 Wi-Fi、防火墙已放行」的前提下**仍然连不上 `http://`**，原因在 App 侧的明文策略：

- Android 9+ 默认禁止明文 HTTP（`android:usesCleartextTraffic`）；
- iOS 的 ATS 默认拦 `http://` 非 localhost 地址（`NSAppTransportSecurity`）。

两者都属于 `mobile/app.json` 的原生配置，修改属于 App 侧变更。本次任务只改 ARTEX 源码，故不动；
实际体验上 debug 包通常已放开，release 包则可能需要补两行配置。

## 7. 通不通与排查

1. 电脑上看端口绑定：`netstat -ano | findstr :8787` 应出现 `0.0.0.0:8787` 或 `[::]:8787`，
   而不是只有 `127.0.0.1:8787`。
2. 手机浏览器先试 `http://<局域网IP>:8787/api/health`，能出 JSON 就说明网络层没问题。
3. 都通了再回 App 登录。
