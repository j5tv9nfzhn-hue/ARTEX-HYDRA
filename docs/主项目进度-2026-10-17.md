## 1. SDK 与工具契约

- 以 go.mod 固定的 norma v0.4.3 声明为依据，不升级或改写 SDK。
- Result 文本读取改用 Flatten，止损信息追加独立文本块；保留已有块、IsError 与 Extra 指导消息。
- 技能正文读取改用 SDK 实际的 Instructions 字段，避免旧 Content 字段残留。
- 修复 Skill 错误计量读取不存在 Output 字段的问题。
- Skill 规范字段为 name；历史 skill/skill_name 通过可校验的兼容 schema 和显式归一处理，冲突字段拒绝。
- 精确的可见技能名优先；兼容已知别名，不再进行模糊前缀或任意子串匹配。
- KB 静态卡片查询零匹配返回空数组，不再将全部卡片伪装成命中；返回来源、匹配数和截断标记。
- 历史恢复仅处理有成功 tool_result 配对的 Skill 调用；失败、未完成、无配对调用不解锁 MCP。恢复也通过可见注册表校验别名。
- 代码内 Skill 示例统一为 name；tactical_kb 示例使用真实 mode，删除不存在的 action=search/action=record 指引。
- 历史别名依当前可见清单解析，没有对更换同名技能后的语义做版本锁定；应避免在运行历史仍需恢复时重分配技能名称。
- 旧数据库中的人工/历史 prompt 不在本轮自动改写；若仍含旧例子，需要操作者后续审阅。运行构造时的新路由与工具描述不等于数据库 prompt 已全部迁移。

## 2. 执行层止损与证据边界

- 修正旧识别器与真实返回结构的不一致：HTTP 的 status、Fuzz 的 hits_count / total_tested；Fuzz 支持真实 url_template 输入。
- 单次 AugmentTools 运行内，http_request / http_fuzz 的相同工具、方法、完整 URL、请求上下文重复得到三次相同负反馈后，后续同键调用在执行前拒绝。
- 同键调用串行进入门禁，避免并发请求同时跨越阈值；其他键独立。等待支持上下文取消。
- 不归并不同资源 ID、查询值、凭据或请求正文；这样会更保守，但不会把不同资源/身份当作同一个硬阻断对象。
- 截断或无法解析的 HTTP 输出不作为完整负反馈证明。工具错误不推断后端技术栈。
- 本轮没有模型可调用的重置入口；新执行轮创建新状态。Bash、MCP、其他工具、批量调用内部请求及跨轮调用不在此门禁范围内，它不是安全沙箱，也不是跨轮持久化阻断。
- 修改了知识卡片、Planner 说明及相关内置技能，避免把固定响应、有限字典未命中或少量试验写成“100% 证明没有漏洞/使用 ORM”。止损、目标达成与充分证据的证伪是不同结论。
