# 成本与预算：后端整改方案（会话级）

> 目标不是"多加一个预警开关"，而是把**已经存在于任务侧、但缺失于会话侧**的预算能力补齐，
> 并把口径从"收尾后暂停"改成"执行中降级 / 超线收尾"。
> 覆盖范围：控制台聊天 + Harness 工作台（两者共用同一条后端会话执行路径）。
>
> **两条硬约束**（本次按此自查并已修正）：
> ① 不做不稳定负优化——不加高频查询、不做静默掐断、不做静默能力削除；
> ② 不与既有功能产生歧义——闸门归属唯一、计量口径唯一、显示口径一致。

---

## 0. 现状审计（对着代码逐条核）

| 能力 | 现状 | 落点 | 缺口 |
|---|---|---|---|
| 任务级 Token 预算 | **有**，但是"run 收尾后读账本 → 暂停整个任务" | `server/engine.go checkTokenBudget`、`tasks.token_budget`、`default_task_token_budget` | 收尾后才生效；需要人工恢复；**不覆盖会话** |
| 会话级 Token 预算 | **无** | — | 控制台聊天 / Harness 只有 `maxTurns` + `maxDuration` |
| 用量采集 | **有** | `agent/capture.go` 的 `harness.KindUsage` → `usage` 活动；`result` 行挂本轮累计 | 采集了但没有任何处置 |
| 计价 | **有** | `server/pricing.go`（`price_table`，最长子串匹配） | 只能按 task/intent 聚合，会话无 model 归属 |
| 上下文压缩 | **有** | `agent/compaction.go`、`compaction_layers.go` | 触发时机不可按预算调整 |
| 工具输出截断 | **有** | `assembly.go`：历史 12000 字符 + 落盘 `ToolOutputDir` | 只在历史侧 |
| 循环检测 | **有** | `agent/loop_breaker.go` | 与预算不联动 |
| 提示瘦身 | **有** | `agent/prompt_slim.go` | — |
| 早停 | **部分** | `maxTurns` / `maxDuration` | 与花费无关 |
| 失败代价控制 | **无** | — | 无"注定失败"判定 |
| 价值记账 | **部分** | `finding_recorder`、`first_finding_ms` | 会话时间线看不到"花了多少换几条发现" |

**结论**：供给侧（瘦身、压缩、落盘、缓存）做得不错；缺的是**需求侧的刹车**，
而刹车恰好只装在任务上，不在用户天天用的会话上。

## 1. 三条设计原则

1. **默认可见，但不默认拦截。**
   默认预算 40 万 token（约十几到几十轮）**只用于显示**；只有**显式配置**了
   `default_conversation_token_budget`，才自动进入 `enforce`。
   理由：零配置用户不该因为升级后被无声掐断——那是负优化，不是保护。
2. **在执行中生效，不是收尾后。**
   预算要在"还能停"的时候起作用，所以挂在 usage 事件上（每轮模型调用一次）。
3. **降级优先于停止，停止必须可恢复；且降级必须可见。**
   接近上限先砍最贵的能力，真越线才收尾；收尾写结构化记录而不是抛错误；
   关闭能力这件事本身要留一条系统记录，不做静默削除。

## 2. 与既有功能的关系（防歧义，逐条写死）

| 关系 | 规则 | 为什么 |
|---|---|---|
| **会话预算 vs 任务预算** | 带 task 归因的 run（触发器 / 复测 / reporter）**不挂会话级闸**，`budgetLimit=0`，由 `engine.checkTokenBudget` 负责 | 同一笔消耗不能被两个口径不同的预算各判一次，否则出问题没人说得清是谁停的 |
| **预算计量 vs 页面 token 显示** | 预算按 **input+output**（不含缓存读/写），与 `TaskTokenTotal` 同口径；页面原有的 token 胶囊仍含缓存 | 缓存读按 0.1x 计价、数量级远大于常规输入，计入会让"预算"和"账单"打架 |
| **预算 vs `maxTurns`/`maxDuration`** | 三者并存，互不覆盖；预算越线有独立原因码 `budget_exhausted` | 停的原因必须可区分 |
| **预算用尽 vs 执行失败** | 用尽 = `Worker:"system"` + `Kind:"text"`，**不置 IsError** | 对齐任务侧 `AbortPausedByTokenBudget` 的既有留痕，避免前端渲染成报错 |
| **降级 vs 用户开关** | `tight` 关联网搜索时写一条系统记录 | 用户自己开的 webSearch 被关掉，必须看得见 |
| **新接口 vs 轮询频率** | 预算**不进** `/messages`（运行中 1s 轮询会变成 1s 一次聚合查询）；前端只在**切会话 + 轮次结束**时读一次 `/budget` | 避免用一次全表 SUM 换一个数字 |
| **数据面** | 不新增列、不做迁移、不改 `llm_usage` 结构 | 回滚只需改设置，不需回滚代码 |
| **提示词 / 工具行为** | 除 `tight` 档关联网搜索外，不改任何提示词与工具行为 | 不污染既有评测口径 |

### 运行时的样子

```
用户发消息
  └─ runConversationTurn
       ├─ budgetLimit = 设置默认值
       ├─ if llmrec.TaskIDFrom(ctx) != "" → budgetLimit = 0   ← 让位给任务预算
       ├─ baseline = db.ConvTokenTotal(conv)
       ├─ ledger = NewConvLedger(id, limit, mode, baseline)
       ├─ ctx = WithConvLedger(ctx, ledger)
       ├─ if Tier()==tight → webSearch=false + 写一条系统记录（可见降级）
       └─ ca.Chat(ctx, ...)
             └─ 每次 KindUsage → ledger.Observe()
                   ├─ <70%   ok
                   ├─ 70–85% watch（前端变色）
                   ├─ 85–100% tight（已关搜索，且已留痕）
                   └─ ≥100%  → cancel(AbortChatBudgetExhausted)
       └─ Chat 返回 → ledger.Exhausted() ?
             ├─ 是 → emitConvBudgetStop()（结构化 payload，可恢复）
             └─ 否 → 原错误路径 / completed
```

### 设置项

| key | 未配置时 | 说明 |
|---|---|---|
| `default_conversation_token_budget` | **无上限**（视图显示 400000 兜底值） | 显式填数后：既是上限，也意味着"要管" |
| `conversation_budget_mode` | **warn**（只显示不拦截）；若已显式填预算则自动 `enforce` | `enforce` 收尾 / `warn` 只显示 / `off` 关闭；非法值回落 warn |

## 4. 档位与行为

| 档位 | 触发 | 当前行为 | 建议后续 |
|---|---|---|---|
| `ok` | <70% | 无 | — |
| `watch` | 70–85% | 前端琥珀色 | 注入提示：优先验证已有假设 |

| `exhausted` | ≥100% | 终止本轮 + 结构化记录 | 前端给"提高预算并继续" |

| 项 | 为什么这次不做 | 需要动哪里 |

## 6. 验收

**静态（不编译也能核）**
- `grep ConvLedgerFrom agent/capture.go` → 1 命中
- `grep DefaultConvTokenBudget server/conversations.go` → 装配处命中
- `grep "conversations/{id}/budget" server/server.go` → 1 条
- `grep '"budget"' server/conversations.go` → **0 命中**（确认没有回到 /messages 的高频查询）

**运行**
1. 不配置任何设置：页头出现预算胶囊，但长会话**不会被拦**（warn）；
2. 设 `default_conversation_token_budget=5000`：自动 enter enforce，第 N 轮收尾；
3. 活动流出现一条 `Worker=system`、非 IsError 的「本轮已收尾：…预算用尽」；
4. 触发器/复测会话仍由任务预算管，**不会**出现会话级收尾记录；
5. `tight` 档且 agent 开了 webSearch：出现「本轮关闭联网搜索…」的系统记录；
6. 调高预算后重发 → 正常继续（checkpoint 未丢）。

**上线后指标**
- token / 成功任务；浪费比 =（失败+重试 token）/ 总 token；缓存命中率；各档位停留时长

## 7. 上线顺序与回滚

1. **先观察**：默认 warn，把 `tier` 分布与真实用量看一眼；
2. **再收紧**：按 P95 用量设定预算（填数即自动 enforce）；
3. **回滚**：`conversation_budget_mode=off` 或把预算设回 0 —— 一条设置，不涉及代码回滚。
