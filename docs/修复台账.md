## 四、当前进行中的工作：PostgreSQL → SQLite 迁移

### 4.1 已完成

| 项 | 内容 | 验证 |
|---|---|---|
| schema 转换器 | `db/schema_translate.py`，PG→SQLite 自动转换 | 185 条语句应用成功，连续三次幂等 |
| SQLite schema | `db/schema_sqlite.sql` | 49 表 / 88 索引 / 20 触发器，与 PG 版表数一致 |
| 引擎开关 | `config/engine.go`（含 4 个测试） | `ARTEX_DB_ENGINE=sqlite` 显式开启；默认仍为 postgres |
| SQLite 打开路径 | `db/open_sqlite.go` | 与 PG 分支共用 `db.DSN()` + `db.Open()` 分流 |
| 兼容函数 | `db/sqlite_compat.go`：`regexp()` / `now()` | 补 `now()` 后 SKIP 从 124 归零 |
| 并发正确性 | `_txlock=immediate` | 消除 deferred 事务的读-判断-写竞态窗口 |

### 4.2 关键实测结论

1. **`_texttotime` 只认 DATETIME 族声明类型**：`TEXT` 列无法 Scan 成 `time.Time`，`TIMESTAMP`/`DATETIME` 才可以。88 个时间列已改声明。
2. **存储格式必须对齐驱动**：`_time_format=sqlite` 实为 `"2006-01-02 15:04:05.999999999-07:00"`（空格分隔 + 数字时区），schema 默认值与 `now()` 已对齐，否则同列并存两种格式会破坏排序。
3. **`json.RawMessage` 扫描失败源于驱动返回 `string`**：实测 `TEXT→json.RawMessage` 失败、`TEXT→[]byte` 成功、`BLOB→json.RawMessage` 成功。
4. **`FOR UPDATE SKIP LOCKED` 队列抢占必须重写为单条原子 `UPDATE ... RETURNING`**，不能简单删除——否则两个抢占者会读到同一批待处理行并各自插入重复投递。
