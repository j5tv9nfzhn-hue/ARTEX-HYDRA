## 0. 一句话定位

ARTEX-REA 是一个**AI 自主渗透测试与逆向工程系统**：Go 单二进制后端 + Next.js 静态前端，以 SQLite 单文件为唯一存储，由 LLM Agent（planner / worker / mainagent 多角色）驱动「资产侦察 → 流量拦截与取证 → 漏洞验证 → 逆向分析 → 报告产出」的完整链条，并通过**进程内 MCP 工具集 + 外部 MCP（REA / WPE64 / ScopeSentry）+ 技能包**扩展能力边界。

上游血统：基于 Autumn-27/ARTEX，本分支做了简体中文化、PostgreSQL→SQLite 迁移、发布通道自建（`j5tv9nfzhn-hue/ARTEX`）。

## 2. 技术栈与运行形态

**后端**：Go `1.26.3`，模块 `github.com/Autumn-27/artex`。
关键三方库：`norma v0.4.3`（LLM/Agent/MCP SDK，项目自研上游）、`go-mitmproxy v1.9.2`（记录代理）、`modernc.org/sqlite v1.52.0`（纯 Go SQLite，无需 CGO）、`miekg/dns` + `projectdiscovery/dnsx`（DNS）、`golang-jwt/v5`（鉴权）、`klauspost/compress`。

**前端**：Next.js 16 + React 19 + TypeScript + Tailwind 4 + Biome，UI 基于 Radix / base-ui / shadcn；图可视化用 `@antv/g6`、`@xyflow/react`；表格 `@tanstack/react-table`；状态 `zustand`；i18n `next-intl`（zh / en / es，默认 zh）。构建产物以 `-tags embedui` 内嵌进单二进制。

**运行形态**（`cmd/artex`）：

```
artex -addr 127.0.0.1:8787   # 默认仅回环，显式 :8787 才对其他主机开放
      -data  <数据目录>       # SQLite 数据目录，默认可执行文件旁 data/
      -proxy 127.0.0.1:8788   # 流量记录代理（空则关闭）
      -reset-password         # 单次模式：重置管理员密码后退出
```

双 MCP 传输：`stdio`（桌面客户端）+ `Streamable HTTP`（Web/隧道，带 Origin/Host 校验、会话 TTL、可选 token）。

## 4. 六条核心能力链

### 4.1 Agent 自主编排
`goals → planner → worker` 三段式 + `mainagent` 汇总；探索过程沉淀为**图**（`explorations` / `exploration_nodes` / `exploration_edges` / `exploration_anchors`），支持意图（intent）粒度推进与「0 意图」判定；上下文有压缩分层（`compaction_state`、plan/worker 注入瘦身 `prompt_slim.go`）、检查点与回滚（`checkpoints`）、预算与耗时账本（`convbudget.go`、`taskclock.go`）。

### 4.2 流量拦截与证据链
内置 go-mitmproxy 记录代理（:8788）→ SQLite 流量库；`intercept` 做管控规则与「判定模型」复核（结论含置信度），`guard` 做命令防护，`evidence` 生成证据快照并与 finding 绑定（`traffic_evidence_snapshots`、`finding_traffic_bindings`）。审批有全局记录、任务内拦截、对话卡片三种入口，均可展开详情。

### 4.3 逆向工程（REA 单引擎优先）
契约分层 `unverified / basic / deep`，核心操作集 `status / functions / decompile / xrefs / callgraph`；地址纪律严格区分 **RVA**（functions/decompile/xrefs/callgraph/modules/imports/exports）与 **file_offset**（strings）；多模块以 `(module, address_kind, address)` 三元组为身份；提供完整导出 bundle、配额与清理（`/api/re/sweep`）。外部引擎经 `REProviderConfig` 通用映射层接入（Ghidra / IDA 为骨架）。

### 4.4 工具生态：进程内 MCP + 外部 MCP + 技能
- **进程内（纯 Go，不拉子进程）**：`artex-recon`（dns_recon / port_probe / tls_inspect / tech_hints）、`artex-webscan`（http_send / http_fuzz / dir_probe / param_probe / jwt_inspect / sqli_probe）、`artex-binscan`（file_identify / pe_info / strings_scan / entropy_scan / ioc_extract）。命名统一 `mcp__<server>__<tool>`。
- **外部 MCP**：REA（`rea_*` 预设，如 `rea_open_sample`、`rea_list_strings`）、WPE64（14 工具契约：抓包/改包/重放/规则/落盘）、ScopeSentry（资产同步）、浏览器（L1：系统 Chrome/Edge 走 CDP，零额外磁盘；Camoufox 降为按需档）。
- **技能包**（14 个）：`api-recon` `web-vuln-tactics` `exploit-kb-patterns` `expert-triage-pivot` `reverse-engineering` `rea-mcp` `wpe64-mcp` `mitmproxy-traffic` `human-verification` `scopesentry-mcp` `wasm-cloud-saas-tactics` `ai-gateway-logic` `ai-coding-sandbox-tactics` `camoufox`，由 `skill_router.go` 路由、`tool_contract.go` 做别名、`db` 播种可见性（V2 开关只补新包、不复活用户关闭的旧包）。

### 4.5 模型池与成本
`llmpool` 按角色路由 + 私有熔断 + 备用链（`agent_llm_fallbacks`）；`llmrec` 记录调用与 token；`llmtest` 做轻量连通性测试（无 tools/system/stream）；价格表 `server/pricing.go` 做最长子串匹配与读时计价，费用按会话/角色聚合（`llm_usage`、`TokenByWorker`）。

### 4.6 资产、报告与通知
资产图（`companies` / `assets` / `company_scope`）支持 ScopeSentry 同步、公司范围归并与资产拦截规则；`findings` 有处置态与**复核态**双维度（`finding_retests`：reproduced / fixed / inconclusive）；`report` 出报告；`notify` 支持多渠道（`notification_channels` / `events` / `deliveries`）。

## 7. 安全设计（本分支重点加固项）

1. **首次初始化防抢占**：`POST /api/auth/init` 必须提供仅服务端控制台显示的 `setup_token`，错误尝试有速率限制（`ARTEX_SETUP_TOKEN` / `ARTEX_ADMIN_PASSWORD`）。
2. **默认只绑回环**：`-addr` 默认 `127.0.0.1:8787`，非回环 + 无密码会告警。
3. **JWT 密钥由密码哈希派生**：改密即废除全部旧 token（UI / `reset-password.sh` / 直接改库都生效）。
4. **CORS 允许列表**（`ARTEX_CORS_ORIGINS`），服务端最短 8 位密码。
5. **凭证静态加密**：API Key 与 MCP env 密钥落库加密（`credential_crypto.go`、`mcp_env.go`）。
6. **命令防护与管控**：`guard` 审批钩子 + `intercept` 规则/判定，审计带调用 ID 与并发匹配。
7. **数据治理**：保留策略默认 **30/14/30 天**后台自动执行；活动保留 14 天 + 10 万行双闸门；只读连接池、写队列观测。
8. **自更新双闸门**：更新源白名单 `j5tv9nfzhn-hue/ARTEX` + SHA256 校验；自动检测默认开、自动安装默认关。

## 8. 工程与发布体系

**唯一构建流水线** `.github/workflows/release.yml`：

```
gate      tag 格式 + go build ./... + go vet + go vet -tags embedui + gofmt + golangci-lint   ← 硬门禁
frontend  npm ci → npm test / biome（仅信号）→ build:static（含 TS 类型检查，硬门禁）
binaries  6 目标交叉编译 + 头校验 + 打包
release   校验 6 个 zip → sha256sum → 建草稿 → 上传 → latest.json → 转正（失败删草稿、保 tag）
signals   go test / 语言检查 / 文档链接（continue-on-error，只报告不拦）
```

配套 `.github/workflows/detections.yml`（规则与指标回归）与 `verification-helper.yml`（手动，单模块）。

**门禁口径**：编译/静态/类型失败**必拦**；测试失败只作健康度信号（红了要显著标注，不许删测试求绿）；发布失败原子回退。

**AI 助手作业约定（`AGENTS.md` + `docs/开发与发布约定.md`，最高优先级）**：
- 本机**只读只写，不构建**（`go build/vet/test/run`、`gofmt`、`golangci-lint`、`npm` 系列、任何打包脚本，含经 MCP shell 间接调用）；
- 访问 GitHub 一律走代理 `127.0.0.1:7897`，按次传参不写全局 config，20 秒无响应即判不可达，最多 3 次；
- **推送即返回**，不轮询 CI；唯一串行要求是 tag 必须在新 commit 已到远端之后；
- 用**静态自检**替代编译：核对 import / 符号 / 签名 / 字段 / i18n 键 / golden 断言；
- 一次语义完整改动 = 单个提交，**中文提交信息**，不提交构建产物与密钥。

## 11. 风险提示

1. **验证真空**：本机不构建是硬约定，因此所有改动在推送前只能达到「静态看是对的」；真正的确定性来自云端 gate。接手时不要把静态核对说成「跑通了」。
2. **规模成本**：595 个 Go 文件 + 222 个 server 文件 + 62 张表，改动前必须 `grep` 定位符号，凭记忆写符号名必然出错（仓库内已有 `errmsg_catalog.go` gofmt 形态导致编译门禁失败的先例）。
3. **Windows 生产机**：MCP 的 `shell` 走 cmd/PowerShell，路径 `C:\...`，编码与分隔符需注意（仓库有专门的 UTF-8 审计文档）。
4. **能力面本身是双刃剑**：内置 `shell`、mitmproxy 解密、逆向、`sqli_probe` 等工具意味着一旦鉴权失守即等于交出主机。当前远程 MCP 端无 token（见上一份连接报告），建议尽快补上。
5. **共用 `web/messages/zh.json`**：新增界面文案必须同时补键，否则 i18n 检查与前端会漂移。

## 12. 结论与建议路线

**结论**：这是一个**完成度相当高的单二进制安全平台**——分层清晰（4 层 + 2 平台层）、数据模型完整（62 表覆盖资产/任务/证据/逆向/治理）、测试密度高、发布链路工业化（单一构建 + 分层门禁 + 原子回退），并且在最近 10 天内连续完成了架构断层收口、流式渲染、存储治理、浏览器栈换血四条主线。

**它的核心竞争力不在「工具多」，而在三处契约化设计**：
1. **证据链**：finding ↔ 流量 ↔ 证据快照 ↔ 复核结论，四者都有表与状态机约束；
2. **工具契约**：MCP 命名、契约分层（tier）、地址纪律（RVA vs file_offset）——把「工具能调」与「引擎 ready」分开判定；
3. **门禁分层**：编译必拦、测试只报，避免了「测试红导致发不出包」和「为了绿去删测试」两种常见腐化。

**建议下一步（按投入产出排序）**：
1. **补鉴权**：远程 MCP 加 `-token` + 固定域名隧道（当前是裸奔的公网 `shell`）。
2. **收口未闭环三件**：`reOpen` 硬拒绝 → REA/WPE64 `tools/list` 刷新与真机联调 → 单引擎验收清单执行。
3. **规划 `v2.3.0` 范围**：把开发总清单里「源码已落地 / 验收待完成」条目按可验收判据筛一遍，形成一版以「验收」而非「新增」为主题的版本。
4. **长期**：`server` 包已 222 文件，可考虑按域（auth / re / findings / traffic / mcp）做一次纯搬移的包级拆分，但需在测试基线稳定后进行，且一次只动一个域。
