# ARTEX 人机验证链路加固与验收准备

日期：2026-10-18。本阶段继续源码开发，不执行本地编译、测试、程序启动、数据库操作或第三方目标验证。以下是代码审查发现与源码修订，不是运行验收结论。

## 审查发现与处理

| 发现 | 源码处理 |
|---|---|
| 原父级管道Scan主要依赖整链取消，单请求取消不能直接结束阻塞IPC | 每次IPC采用独立取消/5秒上限（握手2秒），取消时关闭stdin/stdout并取消进程；保留context错误链 |
| 原版本/Provider在第一次HTTP请求返回后才校验 | 升级IPC v2，先无目标URL地交换hello/ready，成功前不发HTTP命令；旧helper不自动降级 |
| 缺少响应关联标识，坏/迟到帧可能污染后续请求 | 握手request_id=0，HTTP request_id按1..6递增，响应必须同号；错序/坏帧/取消后当前会话永久禁用，不重放 |
| 子进程仅靠父级限制同源 | hello固定规范化origin，子进程逐帧独立同源校验，并锁定profile/协议/proxy/CA |
| 原响应主要验证大小/版本，未完整约束Header与认证信息 | 限制Header token、控制字符、重复大小写、字段/值数量与总长；验证状态码、实际HTTP协议、无正文状态与非空调用方Header保留 |
| 原固定错误信息过于笼统，或可能直接信任子进程错误文本 | helper错误仅映射白名单代码；flow增加failure_code，覆盖握手、IPC和响应契约失败，不回显秘密或任意错误原文 |
| 标准flow的受限transport克隆由全局sync.Map长期持有 | 改为每链持有一个克隆、复用并在结束时关闭空闲连接；指纹路径不再创建无用标准克隆 |
| 原手动CI只覆盖Linux独立模块 | 手动选择Linux/Windows/both，最多并行1个；可额外勾选父级IPC fixture，默认不增加主模块编译 |

## 新契约：IPC v2

主程序与独立helper必须配套更新。`req/v3@v3.59.0`仍是依赖Provider，不能代替IPC版本校验。已有v1 helper需要操作者按需重新构建；本次不构建或安装二进制。

- hello/ready：version=2、request_id=0，无目标URL、method、headers、body；绑定origin及profile/http_version/proxy/ca_pem。ready不代表TLS/站点通行验收。
- request/response：最多6次，request_id=1..6；固定会话配置，只接受同origin GET/HEAD/POST。父级继续控制Cookie jar、跳转、流量证据与提交去重。
- 每帧<=128KiB；握手2秒、单请求<=5秒，仍受整链默认10秒/最多15秒约束。握手不计HTTP RoundTrip；transport透明重试不逐一计数。
- 请求正文24KiB、响应32KiB+1溢出字节、响应头32KiB；Go请求Header快照16KiB（并非transport自动生成头与线上顺序的完整抓包）。请求Header仍8KiB，包含运行时Cookie。
- 一次IPC写入/读取失败或取消即关闭会话，不重启替代helper或重放。所有pipe端点明确关闭，Wait回收只执行一次，并设置500ms WaitDelay减少继承管道拖延。
- helper本身是操作者可信程序，不是恶意进程/子孙进程/OS资源的强隔离沙箱；Kill/Wait与Windows生命周期的实际行为仍须运行验证。

认证、Cookie及其他非空调用方Header不得被helper悄悄替换。User-Agent、Sec-CH-*、Accept-Encoding是已声明的profile/低资源覆盖例外；未实现完整浏览器环境。identity协商与禁止任意压缩解码继续保持。

## 测试源码（均未执行）

父级新增8个断言测试函数和1个测试子进程fixture：

1. 非法版本/协议/状态/Header/正文/会话Header拒绝。
2. 未知helper错误不回显秘密，强制H2及HEAD正文契约。
3. hello成功、Cookie保留、关闭后不可再用、槽位只释放一次。
4. 旧helper在提交URL前拒绝。
5. 请求超时立即中断IPC、保留DeadlineExceeded、禁用会话。
6. 坏JSON、超大帧、错序响应均终止会话。
7. 标准flow transport克隆不再由全局映射复用持有。
8. 排队请求取消不必等待活动请求结束，也不取消尚在工作的会话。

fixture仅在明确test子进程参数/环境下工作，不启动ARTEX服务、不打开网络socket。其源码在本次没有被执行。

独立helper新增4项测试：无握手不发包/hello不访问目标、子级跨源拒绝、系统根拒绝自签证书与显式CA/H2、明确代理与不继承环境。仅使用httptest/本地代理或被本地代理处理的example.invalid标识；不测试第三方防护站点。
