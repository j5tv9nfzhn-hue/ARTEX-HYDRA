# 架构分层与边界约定（批次 7 · 条目 156–164、173–176）

本文归档 ARTEX 后端的**现状分层**、依赖方向与可执行的边界约定，回应清单条目 156–164（乱/耦合/堆砌/四层）与 174–176（魔法串/依赖/接口）。目的：把「缺少清晰的四层设计」收敛为可核对的形态——哪些边界已是硬约定（有集中定义点、有门禁），哪些仍是聚合层里的历史包袱（明确记录，不做一次性全量重构）。证伪条目 155/159/160/161/172 的实测数据见文末。

### 2026-10-16 补记：本轮（批次 2–8 / E）新增模块的层级归属

本轮新增模块全部落在既有分层内，未引入新的层或循环依赖：

- **进程入口：** `cmd/artex/resetpass.go`（`-reset-password` 单次模式，先于自举/端口处理）。
- **API 与编排：** `server/pricing.go`（价目表解析/最长子串匹配/读时计价）、`server/task_notify.go`（`task_status_changed`/`approval_pending` 的 emit 收敛点）、`server/intent_intervention.go`（steer）、`server/checkpoints.go`、`server/env_context.go`、`server/shellcap.go`、`server/toolkind.go`、`server/modalities.go`、`server/llm_pool.go`。
- **角色编排：** `agent/prompt_slim.go`（自动注入瘦身）、`agent/deferred.go`（整段 system 缓存边界）。
- **平台集成：** `llmtest`（独立轻量测试连接，无 tools/system/stream）。
- **存储：** `db/checkpoints.go`、`db/task_env.go`、`db/compaction_state.go`、`db/mcp_env.go`、`db/llmretry.go`、`db/modalities.go`、`db/llm_usage.go`（`TokenByWorker`）。
- **基础设施：** `metrics`（工具错误/重放/中断恢复计数）、`stageerr`、`fsutil`；`notify/task_event.go`。
- **前端：** `web/src/lib/severity.ts`（严重度色彩唯一事实源）、`web/src/lib/sidebar-prefs.ts`（侧边栏偏好）、`web/src/lib/fonts/registry.ts`、主题预设 `web/src/styles/presets/*.css`。

## 边界约定（现行、可验证）

1. **存储唯一出口是 `db`**：SQLite 是唯一引擎，不存在第二后端；路径、DSN 与 pragma 契约只在 `config/sqlite.go` 的 `SQLiteDSNFor` 定义，测试与工具也必须走它（注释中已写明「第二份拷贝漂移」的成本）。
2. **路径解析集中 `config`**：`BaseDir()`/`Path()`/`SkillDir()`/`SQLitePath()` 是文件位置的唯一来源；数据目录由 `--data` 注入 `server.NewManager`，其他包不再各自拼装。
3. **前端只经 HTTP API**：组件不直连数据库；内嵌与否由 build tag 决定（`server/webui_embed.go` 与 `server/webui_stub.go` 一进一 stub，忘带 `-tags embedui` 时首页返回中文 404 提示）。
4. **消费者侧接口隔离**：`llmrec.Recorder` 的持久化依赖收敛为 `recordStore` 接口（仅 `InsertLLMUsage`/`InsertLLMRecord` 两个方法），不再持有具体 `*db.DB` 句柄；数据模型仍复用 `db.LLMUsage`/`db.LLMRecord`（避免复制模型，这是刻意的取舍）。
5. **常量表代替魔法串**：工具 kind 收敛为 `server/toolkind.go` 的四个常量（`command`/`script`/`http`/`shell`），替换原先散落在本包 10+ 处的字面量；这些值同时是数据库列值与前端契约，只保留一个定义点。
6. **格式与静态门禁**：格式由 CI 的 `gofmt` 门禁（setup-go 锁定的 Go 1.26 工具链）唯一把关；静态检查为 `.golangci.yml`（govet，干净基线）＋ golangci-lint（v2.14.0）＋ `.pre-commit-config.yaml` 的 `go` hook。golangci-lint 的 gofmt 内嵌其构建时的 Go 版本，与工具链可能判定相反（2026-10-16 errmsg_catalog.go 事件），故不重复启用。收紧路径：ineffassign、unused、staticcheck、misspell、revive 逐项本地清零后加入，避免一次性引入噪声把门禁架空。

## 命名清理（#11/158）

本批只做小而准的局部重命名：`server/logsink.go` 的 `ll` → `line`、`llmrec` 的存储字段 `pg` → `store`、`server/customtool.go` 的 `pj` → `paramsJSON`。**不做全仓机械重命名**（如 pg→db）：工作区正承载 SQLite 迁移的大量未提交差异，机械替换会撕裂 diff、掩盖真实变更。

## 遗留与不做的事

- `server` 仍是最大的聚合层（66 个生产文件、约 2.6 万行），承载 HTTP API 与管理器胶水；把它继续拆分为更细的 api/service/store 是长期工作，本批只落边界约定与门禁。
- `intercept`/`evidence` 的接口化评估结论：两者的出入参与数据方法数量极多，为它们引入接口会让接口面积大于实现、收益为负；本批只对 `llmrec` 做了消费者侧接口（被 `agent` 广泛使用且依赖面清晰）。
- `enrich`、`fsutil`、`metrics`、`stageerr` 等小包暂无独立测试（纯函数或薄封装），不计入本批范围。
