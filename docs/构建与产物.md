# 构建与产物说明（批次 7 · 条目 173）

回答「编译产物职责是什么、由谁产出、运行时读哪些文件」。对应清单条目 173「编译产物职责不清晰」：这里把构建入口、编译标志、发布包内容与运行时文件落点固定下来。

## 构建入口

| 场景 | 命令 | 说明 |
|---|---|---|
| 日常开发（后端） | `go run ./cmd/artex` | 不含内嵌前端；前端另起 `cd web && npm run dev`。`dev.sh` 一键起前后端 |
| 日常开发（前端） | `cd web && npm run dev` | `/api` 代理到后端 8787 |
| 正式构建（当前平台） | `./build.sh` | 先构建前端再编译；需 Node.js/npm 与 rsync |
| 正式构建（指定目标） | `./build.sh --target windows/amd64` | 支持 linux、darwin、windows 目标 |
| 发布打包 | `./build.sh --release` | 构建三端默认目标（linux/darwin/windows × amd64/arm64）并产出 zip |

前置：Go 1.26 及以上（见 `go.mod`）；构建前端需要 Node.js/npm；打包需要 `zip`；UPX 与 `file` 可选。

## 编译标志（build.sh 固定）

```text
CGO_ENABLED=0 GOOS=<os> GOARCH=<arch> \
go build -tags embedui -trimpath \
  -ldflags "-s -w -buildid= -X main.version=<版本>" \
  -o dist/artex-rea-<os>-<arch>/artex-rea        # Windows 目标为 artex-rea.exe
```

- `-tags embedui`：启用 `server/webui_embed.go`，把 `server/webui/dist`（前端静态导出）编进二进制。**默认构建走 `server/webui_stub.go`，首页返回 404**——这是「忘了带 tag」最常见症状。
- `-trimpath`：去掉本地绝对路径，构建可复现。
- `-ldflags "-s -w -buildid="`：去符号、去 buildid，减小体积。
- `-X main.version=<版本>`：默认取 `git describe --tags --always --dirty`（去掉前缀 `v`），可用 `ARTEX_BUILD_VERSION` 覆盖。
- UPX：默认关闭（`ARTEX_COMPRESS=off`）；`--upx` 强制（缺 upx 直接失败），`ARTEX_COMPRESS=auto` 缺 upx 时保留未压缩二进制；macOS 目标自动追加 `--force-macos`。

## 前端静态导出

```text
cd web && npm ci && npm run build:static   # 产出 web/out
rsync -a --delete web/out/ server/webui/dist/
```

`build.sh` 自动完成上述同步；CI（`.github/workflows/ci.yml` 的 `go-build` job）用 `cp -a` 完成等价操作。`server/webui/dist/` 是生成目录，不手工维护。

## 产物清单

- 单目标：`dist/artex-rea-<os>-<arch>/artex-rea`（Windows 为 `artex-rea.exe`；可用 `ARTEX_OUTPUT`/`ARTEX_OUTPUT_DIR` 改路径）。
- 测试用构建（CI）：`dist/artex-rea-windows-{amd64,arm64}.zip`，经 PE 结构校验后作为 `artex-rea-windows-ci` artifact 上传（保留 14 天）。
- 发布包（`--release` 或 `ARTEX_PACKAGE=1`）：`dist/artex-rea-<版本>-<os>-<arch>.zip`，内容：
  - `artex-rea` / `artex-rea.exe`（内嵌前端、去符号）
  - `start.bat` / `start.sh`（启动监护脚本；页面一键更新需要退出后由脚本重启）
  - `skills/`、`config.example.json`、`README.md`
- `dist/SHA256SUMS`：对 `dist/*.zip` 的 sha256 校验和。

发布流程在 `.github/workflows/release.yml`：推送 `v*` tag 时构建、打包并创建 GitHub Release（发布矩阵为 Linux/macOS/Windows × amd64/arm64）。

## 运行时文件落点

- **配置**：`ARTEX_CONFIG` > 当前目录 `config.json` > 可执行文件旁 `config.json`（先存在者优先）。
- **基目录 `config.BaseDir()`**：可执行文件所在目录；`go run` 的临时/缓存二进制会被识别并回退到当前工作目录，保证开发时读写项目目录。
- **SQLite**：`ARTEX_SQLITE_PATH` > 配置 `database.path` > 配置目录 `artex.db`（默认与 config.json 同目录）。连接约定见 `config/sqlite.go`（WAL、busy_timeout、synchronous=NORMAL、foreign_keys、`_texttotime`、`_txlock=immediate`）。
- **数据目录**：`--data` 参数，默认 `BaseDir()/data`；内含 `tasks/<任务ID>/`（任务工作区）、`transcripts/`（会话记录）、`.delete-staging/`（删除暂存）。
- **技能目录**：`ARTEX_SKILL_DIR` > 配置 `skill_dir` > `BaseDir()/skills`。
- **密钥**：jwt.key 与凭据密钥位于可执行文件旁，不在可浏览的 `data/` 内。
- **单次模式（`-reset-password`）**：离线重置管理员密码后退出——不占端口、不跑自更新、不起后台 worker，只打开 SQLite 重写密码哈希（`cmd/artex/resetpass.go`；`reset-password.sh` 为其封装）。

## 启动监护与一键更新

`start.bat`（Windows）/`start.sh`（Linux、macOS、Docker ENTRYPOINT）是推荐入口：进程退出后按退出码决定行为。

| 退出码 | 行为 |
|---|---|
| 0 | 正常停止，脚本结束 |
| 75（`selfupdate.ExitRestart`，EX_TEMPFAIL） | 立即重新拉起（页面一键更新或回滚） |
| 其他 | 异常退出，1、2、4…秒退避重启，最多 60 秒 |

一键更新链路：旧版进程经 `/api/update/apply` 下载并校验新版本 → 暂存 `artex-rea.new` → 退出 75 → 脚本拉起旧版 → `selfupdate.Bootstrap` 校验并冒烟测试新二进制 → 换装 → 再退出 75 → 脚本拉起新版。下载、SHA256 校验与版本替换全部在 Go 的 `selfupdate` 包中实现，脚本保持简单。

直接双击运行 `artex-rea.exe` 不会自动重启——需要一键更新/回滚能力的部署应使用 `start.bat`。
