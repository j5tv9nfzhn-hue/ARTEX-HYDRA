# #197 数据保留管理界面：实现与验收清单

## 本阶段授权和状态

用户选择继续保留策略管理界面，并维持「仅源码与静态检查」。因此本阶段不编译、不进行类型检查、不运行单元/集成/浏览器测试，不启动 ARTEX，不迁移/打开运行库、不执行实际清理，不提交/推送 Git；独立官网 website/ 排除。

界面源码入口：`/system/retention`，导航为「系统 → 数据保留」。当前运行程序和旧前端产物不会因为源码写回自动获得这些功能。

本阶段没有修改后端 Go、SQL、共享 api.ts、package.json/锁文件、Next 配置或 UI 基础组件。使用已有 React、next-intl、Radix/Shadcn 和 JWT 请求层；不新增依赖。

## 人工维护流程

1. **读取策略。** 页面只在进入时 GET 策略/审计，不自动 PUT 或 POST。旧后端、缺少 schema、身份或结构异常必须明确显示错误，不用默认值冒充当前配置。Mock 在任何维护请求发出前拒绝。
2. **保存策略。** 0 天表示永久保留；用量/通知 30–3650，日志 7–3650，每表上限 1–500。空值、小数、指数和负数拒绝。开关仅允许人工执行，不启用调度；修改后必须保存。
3. **手动预览。** 接受且只接受四个唯一白名单表、完整有界计数、false 的自动清理标记及有效令牌。显示本次固定候选数、更多标记、剩余有效时间；明确预览会新增计划/审计元数据，但不删除业务记录。
4. **重新核对。** 未保存、禁用、策略不同、过期、零候选、请求中或结果待核对都不能执行。若预览返回新策略，更新表单但丢弃令牌，让操作者重新核对后再次预览。
5. **逐次确认。** 弹窗再次显示范围和数量，要求逐字输入 `DELETE_PREVIEWED_ROWS` 并勾选不可撤销确认。普通关闭/取消不会发送执行请求，不用输入框 Enter 自动删除。
6. **执行与结果。** 事件回调内重算门禁；发送前消费本地令牌状态，同步防重入。只有 `committed=true` 且逐表候选数与原预览一致、实际删除+跳过=候选时才显示已确认结果。更多候选绝不自动续批。
7. **异常恢复。** 旧令牌始终弃用；超时、断网、冲突、异常结构都不重试、不宣称回滚或「未删除」。重新读取审计并由操作者核对，仍不明确时停止维护。

## 客户端边界

- 预览令牌仅在内存 ref/请求闭包中，不进入 DOM、URL、普通日志、sessionStorage 或 localStorage。原鉴权层的 JWT 存储方式不在本轮修改范围。
- 关闭确认框会清除确认文字与勾选；编辑、重载、到期、后台切换和重新聚焦会弃用本地预览。客户端弃用不是远程撤销接口；服务端旧计划仍受原 TTL、单次消费与策略保存失效机制限制。
- 同时检查 Date.now 和 performance.now，扣减请求等待和传输余量，不因客户端时钟回拨延长本地租约。客户端时间异常可能保守拒绝；服务端仍决定最终有效期。
- sessionStorage 仅保存一个「结果待核对」布尔标记，以免路由切换/重载隐藏未确认的执行。隐私策略禁用存储时，不能保证跨页面保留提示，但令牌从不恢复。该标记不是审计证据，也不是不可绕过的安全锁。
- 审计读取错误与「成功读取且为空」分开。保留旧表格时明确提示其并非最新；解除待核对前要求重新取得审计并由人确认，不能自动证明某次请求结果。
- GET、策略保存、预览和执行分别保留语义；本地定时器仅更新过期倒计时，不做请求轮询。
- 卸载会终止本地等待并清除令牌；取消等待不保证后端没提交。正在执行时提供离开页面提示，仍无法阻止关闭浏览器或所有站内路由跳转，因此保留非敏感待核对标记。
- 同页 ref 只能减少 UI 重复提交，不能代替服务端鉴权/事务，不能覆盖跨标签或其他客户端。服务端继续负责真实引用、策略、令牌与事务。

## 部署契约

所有请求使用现有相对 `/api/retention/*`，不硬编码后端端口。生产同源部署与开发代理必须分别验收。

后端浏览器变更请求要求 Origin.host 与请求 Host 相同。现有 Next 开发重写的 Host 转发行为尚未实测；若被拒绝，需先检查可信反向代理契约，不能通过去掉 Origin、放宽至任意主机或盲目信任 X-Forwarded-Host 来规避。

新服务源码及 DDL 尚未运行，旧二进制可能 404/返回非 JSON；界面必须停用维护。不得因为页面报错就直接对生产数据库执行 schema。
