# 安全与行为准则

## 一、安全政策



本文说明如何报告 **ARTEX 代码本身的安全漏洞**。ARTEX 是渗透测试工具，但本政策关注的是运行、部署本软件时产生的安全问题，而不是使用工具在外部系统发现的漏洞。

例如：

- Web UI、API 服务（`server/`）中的认证绕过、权限提升、SSRF、注入。
- 保存的凭据、API Key 泄露或以明文存储。
- 绕过人工审批，使 Agent 超出授权范围调用工具的缺陷。
- 供应链或依赖安全问题。

## 报告方式

**不要把漏洞细节提交为公开 Issue。** 修复前公开可能导致漏洞被滥用，请使用私密渠道：

1. 仓库 **Security** 页中的 **Report a vulnerability**，即 GitHub Private Vulnerability Reporting。若仓库已启用此功能，报告只对维护者可见。
2. 若尚未启用，请只提交“希望建立安全问题私密联系渠道”的最小请求，不包含敏感细节，等待维护者提供私密渠道。

有助于快速分类的信息包括：

- 受影响组件和版本，注明 Release tag 或提交哈希。
- 复现步骤、影响范围及能够造成的后果。
- 如可提供，附概念验证（PoC）及建议缓解措施。

## 处理流程

- 收到报告后，在合理时间内确认收件并评估有效性、严重程度。
- 修复准备就绪后与报告者协调公开时间，实行协调披露；修复前不公开细节。
- 经报告者同意，可在公开时注明其贡献。

## 支持范围

本仓库是由志愿者维护的 ARTEX 分支，当前默认使用简体中文。安全修复以**最新默认分支**为基准，不保证回补旧版本。

若问题来自与本地化无关的上游代码，也建议向 [Autumn-27/ARTEX](https://github.com/Autumn-27/ARTEX) 报告。原分支在 2026-10 曾记录该仓库无法公开访问；这不等同于确认其永久删除。

## 不在本政策范围内的报告

- 在外部系统发现的漏洞，应报告给该系统所有者。
- 未经授权对他人系统运行工具所产生的问题；这种使用本身违反[使用范围](../README.md#-先读这一节)及适用法律。
- 工具在授权范围内按设计执行渗透测试这一事实本身。

若发现 ARTEX 被滥用，请通过受害系统所有者及相关机构的合法举报流程处理，而不是将攻击细节公开提交到 GitHub。

## 二、行为准则



## 我们的承诺

维护者和贡献者承诺为所有参与者提供相互尊重、免受骚扰的协作环境，无论其年龄、体型、残障、民族、性别、经验、国籍、外貌、种族、宗教、性别认同或性取向如何。

## 我们的标准

有助于营造积极环境的行为包括：

- 使用尊重他人的语言。
- 尊重不同的观点和经历。
- 得体地给予和接受建设性意见。
- 优先考虑整个社区的利益。

不可接受的行为包括：

- 使用性暗示语言、图像，或给予他人不受欢迎的性关注。
- 嘲弄、侮辱、贬低，以及人身或政治攻击。
- 在公开或私人场合骚扰他人。
- 未经同意公开他人的私人信息，如真实地址或联系方式。
- 其他在专业协作环境中不适当的行为。

## 安全工具使用的特别规定

ARTEX 是进攻性安全工具，不得利用社区的 Issue、PR、讨论空间：

- 请求、分享或鼓励针对未经授权的实际生产系统的攻击。
- 交换针对特定目标实施攻击的操作信息。
- 协助超出[使用范围](../README.md#-先读这一节)或违反适用法律的行为。

## 责任与执行

维护者有权并有责任修改、拒绝或删除不符合准则的评论、提交、Issue、PR 及其他贡献，并可临时或永久限制不当行为者的参与。

## 举报

如遭遇或目睹不可接受的行为，请私下联系仓库维护者，可使用 [SECURITY.md](07-安全与行为准则.md) 说明的私密渠道。所有报告都会接受审查，并根据具体情况采取适当措施。举报人的身份应受到保护。

## 来源

本准则参考 [Contributor Covenant](https://www.contributor-covenant.org) 2.1，并结合本项目的安全工具使用场景调整。
