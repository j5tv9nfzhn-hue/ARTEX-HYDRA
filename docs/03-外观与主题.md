# 外观：皮肤与主题预设

> 代码位置：`web/src/styles/`（令牌与皮肤）· `web/src/lib/preferences/theme.ts`（选项表与切换）
> 现状：**2 套皮肤** × **9 套预设**

ARTEX 的外观由**两个正交维度**决定：

| 维度 | 取值 | 改的是 | 默认 |
| --- | --- | --- | --- |
| **皮肤 skin** | `classic` 经典 · `editorial` 纸本 | **界面语言**：版式、发丝线、等宽数字、有无卡片与阴影 | `classic` |
| **预设 preset** | 九套（见 §2） | **颜色令牌**：主色、纸墨底、圆角 | `default` |

一句话：**预设管颜色，皮肤管版式。** 切皮肤不动你选的颜色，切预设不动版式结构。

---

## 1. 皮肤：经典 / 纸本

### 1.1 两条硬规矩

1. **经典皮肤零影响。** 纸本的每一条规则都挂在 `:root[data-skin="editorial"]` 之下；回到 `classic` 时一条都不生效。这是本节所有改动的底线。
2. **纸本只有一种颜色。** 切到纸本时预设被钉死为「纸本」，预设下拉同时置灰——版式语言已经换了，再让颜色跟着九套色板漂移，就不再是同一个主题。

### 1.2 怎么切

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 偏好浮层「外观」 | 右上齿轮 → 第一组 | 经典 / 纸本 二选一，带一句说明 |
| 顶栏快捷按钮 | 齿轮右侧的字形图标 | 一键来回切，不用开浮层 |
| 命令面板 | ⌘K 搜索「皮肤」 | 同上 |

### 1.3 纸本皮肤改了什么

| 项 | 经典 | 纸本 |
| --- | --- | --- |
| 容器 | 卡片 + 阴影 | 无卡片、无阴影，靠 1px 发丝线与留白分层 |
| 圆角 | 跟随预设 | ≤ 4px |
| 数字 | 比例数字 | 等宽数字（`tabular-nums`） |
| 页签 | 填充式 | 下划线式 |
| 标题 | 跟随预设 | 衬线，仅作用于 `.font-display` 与 `h1/h2` |

### 1.4 版块原语（`data-editorial`）

纸本皮肤引入一组版块原语，供页面声明自身结构。它们**默认全部不渲染**，只在纸本皮肤下生效：

| 锚点 | 作用 |
| --- | --- |
| `secnum` | 版块编号（`01`、`02`…）。默认 `display:none`，因此已有容器可直接加，不改结构、不影响其他主题 |
| `apibar` | 版块数据来源（后端方法名列表），便于排查这块数据从哪来 |
| `panel` / `Panel` / `PanelGrid` | 版块容器 |
| `Sheet` 的 `index` / `api` 属性 | 给既有版块挂编号与接口锚点 |

> ⚠️ 新增任何 `data-editorial` 取值时，必须在 `editorial.css` 里补一条**默认隐藏**规则，否则会在其余预设下以无样式文本漏出。

## 2. 预设：九套

预设只动颜色令牌，不动版式。九套并存、互不影响：

| # | 名称 | `value` | CSS 文件 |
| --- | --- | --- | --- |
| 1 | 默认 | `default` | — |
| 2 | 琥珀终端 | `amber-crt` | `presets/amber-crt.css` |
| 3 | 粗野主义 | `brutalist` | `presets/brutalist.css` |
| 4 | 深空指挥室 | `command` | `presets/command.css` |
| 5 | 矩阵绿 | `matrix` | `presets/matrix.css` |
| 6 | 纸本 | `paper` | `presets/paper.css` |
| 7 | 柔和流行 | `soft-pop` | `presets/soft-pop.css` |
| 8 | 柑橘 | `tangerine` | `presets/tangerine.css` |
| 9 | 双墨 | `two-inks` | `presets/two-inks.css` |

### 2.1 纸本 / Paper

设计来源是《金融时报》的 Origami 设计系统，但只取机制、不取表层：

| 取向 | 做法 | 依据 |
| --- | --- | --- |
| 纸要亮 | `oklch(0.962 0.010 86)` ≈ `#F5F2EB` | FT 的 paper `#FFF1E5` 明度在 0.96 以上，靠色相偏暖而非压暗；压暗会读成「陈纸 / 灰尘」 |
| 主色不是红 | `--primary` 走紫青 `#197075`，红让给 `--destructive` | FT 的分工：青绿做链接与主操作，酒红只做栏目名。按钮和真错误不撞色 |
| 圆角不过 4px | `--radius: 0.25rem` → 派生 0/2/4/8px | 印刷品的刀切边 |
| 阴影归零 | `--shadow-*: none` | 层级交给 1px 描边与留白 |
| 字体分工 | 衬线只管 `.font-display` + `h1/h2` | 报纸感来自字体分工，不是纸张纹理；衬线在 12–13px 下辨识度更差，正文/数字/表格一律无衬线 |
| 图表是「印刷的图」 | `--chart-1..5` 用一条暖墨阶 | 不引入第二套彩色 |

**浅色实测**（纸 `#F5F2EB`）：正文 16.06:1 · 次要文字 5.87:1 · 主色作文字 5.18:1 · 白字压主色 5.78:1 · 危险色 5.74:1 · `--border` 2.14:1 · `--input` 3.32:1。
**深色**（`#17140F`）：正文 15.0:1 · 次要 7.41:1 · 主色 8.14:1 · 危险 5.53:1。

> hover 面（muted / secondary / accent）对比度**必须 ≥ 1.12:1**。第一版给的是 1.05–1.08，鼠标移上去几乎没有反馈——和「双墨」踩的是同一个坑。

### 2.2 双墨 / Two Inks

这套预设解决的不是配色，是**阅读疲劳**。`node scripts/audit-density.mjs` 的基线：

| 指标 | 处数 | 文件数 | 含义 |
| --- | --- | --- | --- |
| `text-xs` | 1180 | 111 | 正文在用 12px，不是注脚 |
| 硬编码色相 `-400/500/600` | 607 | 50 | 琥珀 189 / 红 123 / 翠绿 119 / 蓝 57… |
| `animate-*` | 135 | 51 | `animate-fade-up` 22 处、`animate-spin` 48 处（spin 是功能性的） |
| `shadow-*` | 49 | 28 | 层级靠阴影而不是排版 |
| `uppercase` + `tracking-*` | 39 | 17 | 中文界面里是纯装饰 |

**做法**（全部锁在 `[data-theme-preset="two-inks"]` 下，其余预设不受影响）：

1. **有彩色归零**——在预设作用域内重映射 Tailwind v4 的 `--color-*` 变量：10 个色族压成一条灰阶（`--400` 仍比 `--600` 亮，明度层级不丢）；`red`/`rose` 映射到专色，使**全站唯一的有彩色 = 需要你动手的东西**；其余 10 个低频色族别名过去。
2. **阴影归零**，层级交给 1px 描边（14% / 30% / 50%）与留白。
3. **装饰动效归零**（fade-up / pulse / pulse-soft / glow-once），`spin`、`in`、`out`、`accordion` 保留。
4. **微型字号抬一档**：`text-xs` 到 12.8px / 1.55。

**为什么改变量而不是改组件**：Tailwind v4 的工具类引用变量而非内联值（`.text-red-600 { color: var(--color-red-600); }`），因此重映射一次即覆盖全部调用点，透明度变体自动跟随——**改 1 个文件覆盖 665 处调用**。

**对比度修正确**（第一版把「低密度」做成了「没结构」）：

| 面 / 线 | 修正前 | 修正后 | 判定 |
| --- | --- | --- | --- |
| `--border` vs 画布（浅） | 1.27:1 | **1.93:1** | 卡片边界原本会消失 |
| `--border` vs 画布（深） | 1.60:1 | **2.36:1** | 同上 |
| `--muted` vs 画布（浅） | 1.03:1 | **1.15:1** | hover 填充原本等于没有反馈 |
| `--accent` vs 画布（浅） | 1.11:1 | **1.18:1** | 主 hover 面 |
| `--input` vs 画布（浅） | 1.68:1 | **3.05:1** | 表单控件边界需 ≥3:1 |

要点：**卡片填充色本来就该几乎看不见**（纸压纸是方案的美学前提），但描边和 hover 填充不能跟着消失——前者是信息架构，后者是操作反馈。

**浅色改版（米色纸 → 暖白纸）**：米色 `oklch(0.929 0.014 86)` 大面积铺开后观感是陈纸（明度偏低 + 黄相 + 低彩度）。改为暖白纸，深色**保持原样**：`--background` → `oklch(0.972 0.004 90)`、`--card` → 纯白、色相统一收在 90、彩度压到 0.004（仍不是纯灰，但不显黄）。专色 `#C63417` 未动：纸上 4.94:1、白字 5.36:1 两个方向都达标。

> **一次误判的复盘**：曾收到「屏幕呈灰尘感」的反馈，查到两个原因——(1) Arena 预览 iframe 盖了一层灰罩（像素反解得 a=0.595、G=#A2A2A2，而任务栏与侧栏完全未被压，说明遮罩只作用于预览窗），**那个文件的颜色一直是对的，要看真效果请用浏览器直接打开**；(2) 但米色纸本身也确实偏脏，属于实际问题，故有上述改版。

**已知遗漏（0.17%）**：`.text-xs` / `.uppercase` 是精确类名选择器，`md:text-xs` 这类带变体的不进选择器。全站 1180 处中仅 2 处（`avatar:text-xs`、`item:text-xs`），把这两个变体改成 `text-ui-xs` 即可清零。

## 3. 新增一套预设

不需要改组件，机制已经存在：

1. 在 `web/src/styles/presets/` 下新建 CSS 文件，头部写 `label:` / `value:` 两个注释头；
2. 在 `globals.css` 里加一行 `@import`；
3. 跑 `npm run generate:presets`——`scripts/generate-theme-presets.ts` 扫描注释头，把条目写进 `theme.ts` 的 `// --- generated:themePresets:start ---` 生成区。

外观下拉与命令面板都从 `THEME_PRESET_OPTIONS` 渲染，选中后 `applyThemePreset()` 给 `<html>` 打 `data-theme-preset="<value>"`；CSS 按 `:root[data-theme-preset="…"]` 生效，深色由 `.dark:root[…]` 叠加。

> 生成区之间的内容是**生成器写入**的，不要手改；要改就改 CSS 注释头后重跑。

预设文件里**不加 `@layer` 包装**——CSS 中层外规则优先于所有分层规则，而 Tailwind v4 的工具类在 `@layer utilities` 里，因此特异性（0,2,0 > 0,1,0）与层级优先级双重保证覆盖，与 `@import` 先后顺序无关。

## 4. 回滚

```bash
rm web/src/styles/presets/<name>.css
# 删掉 globals.css 里对应的 @import 那一行
npm run generate:presets
```
