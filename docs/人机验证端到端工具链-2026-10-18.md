# 人机验证端到端工具链：轻量 Go 源码阶段

日期：2026-10-18。此记录描述源码能力与约束，不代表已编译、运行或通过端到端验收。

## 范围

在上一批识别、免费 PoW 和 HTTP 协议选择的基础上，补充 `human_verification_flow`：目标读取 → 明确挑战获取 → 有界求解 → 同会话提交 → 业务确认。

端到端覆盖明确的 ALTCHA salt+number SHA-256/SHA-512 表单协议，不代表所有 CAPTCHA、Cloudflare 指纹/视觉挑战、音频或其他 PoW 都已支持。

不新增人工交互。其他机制由 AI 根据实际可见工具、当前授权与资源预算主动选择降级。没有可用能力时明确返回不支持，不自动安装重型依赖或重复生成同类脚本。

## 工具契约

- `mode=plan`：不发包，返回执行阶段。
- `mode=run`：会执行 GET/GET/POST/GET（可提前结束），POST 必须在已有任务授权内。
- 必填：同源 `target_url`、`challenge_url`、`submit_url`、明确的 `success_body_contains`。
- 可选：业务 `form`、请求头、`payload_field`、HTTP 版本、整链超时、初始目标正文的 CSRF 提取字段与单捕获组正则。
- Cookie 使用单条链路内存 jar，采用已存在的 x/net 公共后缀列表；保留 Set-Cookie 会话，不输出会话文件。
- 初始目标已经满足业务判据时不求解、不提交；PoW 结果不等同业务成功。
- 同源重定向可处理，但不跟随跨源或重发非 GET/HEAD 的跳转。整链复用现有 HTTP 发包、代理与流量记录路径。
- 应用层提交一旦尝试即标记；网络失败也不自动重放潜在已提交的 POST。新的同源参数策略不能绕过这一保护。

## 资源边界

| 项目 | 上限/策略 |
|---|---|
| 新增第三方依赖 | 无；不改 go.mod/go.sum |
| OCR/音频/浏览器/模型 | 不默认提供、不内置、不自动下载或解码 |
| 输入整体 | 64 KiB |
| 请求头 | 32 项、总计 8 KiB |
| 输入表单 | 32 项、URL 编码后 8 KiB |
| 含 proof 的最终表单 | URL 编码后 24 KiB |
| 每响应正文 | 32 KiB，额外 1 字节用于超限检测 |
| 每响应头 | transport 上限 32 KiB |
| 整链时间 | 默认 10 秒，硬上限 15 秒，支持取消 |
| 客户端请求 | 最多 6 次 RoundTrip，包含重定向；不逐一观测 transport 内部透明重试，仍受墙钟限制 |
| 链路内 PoW | 最多 100000 次摘要、1000ms；复用既有有界子工具缓存 |
| 流程状态 | 单工具实例最多 16 个 origin、每 origin 2 条策略、最多 32 条紧凑结果缓存 |
| 重复流程 | 忽略 timeout 的同输入返回缓存，不重新发包 |
| 中间文件 | 不另外保存网页、图片、音频、proof 或 Cookie 文件 |

最终工具输出仅包含阶段、状态、计数、业务判定和 exchange_id，不把完整中间正文或票据交给模型重复处理。既有流量库仍会记录有界请求/响应，可能包含敏感会话及 proof；它不是零存储模式，继续遵循现有访问控制与保留策略。本次不清理已有数据。

资源上限是单专用工具实例/单链路的约束，不是全进程 RSS、累计数据库大小或跨 Worker/跨轮网络流量的硬隔离。Go 标准网络栈、JSON 编码和流量库自身也存在有界处理之外的基础开销，不承诺固定内存数值。

## 接线与兼容

- Worker/pentest 默认工具目录新增 flow；不重置数据库中已有用户工具绑定或自定义提示词。
- Worker 内置工具说明增加流程入口；收尾阶段禁用该有网络/写操作的工具。
- software_re 的 Web 主动工具过滤显式排除 flow，防止添加工具后扩大纯软件静态分析任务权限。
- HTTP 工具普通调用保持原默认 capture/会话行为；只有私有 flow 选项启用小响应上限、共享 jar、同源与请求预算。
- 有流量旁路存储时，flow 记录最终请求实际方法/URL/Cookie；跳转中间响应不因此新增全量独立存储。
- 没有更改数据库结构、运行数据库操作或启动服务。
